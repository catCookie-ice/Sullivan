# SullivanMINI —— 视障公益服务平台 · 项目概述与开发计划

---

## 第一部分：项目简要概述

### 1.1 项目背景

我国有约 1700 万视障人士，他们在日常生活中面临出行难、获取公益资源难、求助难等诸多挑战。现有助盲产品功能单一，缺乏以 **AI 视觉技术** 为核心、整合公益资源的综合性出行辅助平台。

### 1.2 项目名称

**SullivanMINI** —— 取义于海伦·凯勒的启蒙老师 Anne Sullivan，寓意技术充当视障人士的"引路人"。

**中文全称**：视障公益服务平台

### 1.3 项目定位

一个以 **全景分割视觉辅助出行** 为核心创新、纯公益导向的视障人士服务平台。平台不涉及任何商业交易，连接以下四类公益角色：

| 角色 | 核心诉求 |
|------|---------|
| 受护人（视障人士） | 全景分割导航、语音指令控制、安全报警、公益服务申请 |
| 监护人 | 实时查看位置、接收报警、受护人绑定 |
| 志愿者 | 注册、报名公益活动、接收求助广播 |
| 公益机构 | 发布公益活动、提供公益服务（导盲犬/康复/辅具等） |
| 管理员 | 用户管理、机构审核、运营统计 |

### 1.4 核心创新功能

**全景分割视觉辅助出行**：通过受护人端摄像头实时采集画面，利用全景分割模型对环境中的障碍物进行像素级识别，结合空间分析与语音合成，以自然语言实时指导视障人士安全出行。

> 技术链路：摄像头帧采集 → 全景分割（轻量级模型）→ 障碍物空间分析 → 语音引导生成 → TTS 播报

### 1.5 核心业务流程

```
受护人 ──┬── 全景分割导航 ──────→ navigation-service
          ├── 语音指令控制 ──────→ navigation-service
          ├── 安全报警 ──────────→ 通知监护人
          ├── 位置上报 ──────────→ 监护人可查看
          └── 申请公益服务 ─────→ welfare-service

监护人 ──┬── 绑定受护人 ────────→ user-service
          ├── 查看受护人位置 ───→ 实时地图
          └── 接收报警通知 ─────→ 推送

志愿者 ──┬── 报名公益活动 ─────→ welfare-service
          └── 接收求助广播 ─────→ 通知推送

公益机构 ─┬── 发布公益活动 ────→ welfare-service
           ├── 提供公益服务项目 ─→ welfare-service
           └── 处理服务申请 ────→ welfare-service

管理员 ───┬── 审核机构入驻 ────→ admin-service
           └── 运营数据查看 ────→ admin-service
```

### 1.6 技术架构概览

| 层次 | 技术方案 |
|------|---------|
| 视障人士客户端 | Android Native（Kotlin） |
| 管理 Web 端 | Vue 3 + Element Plus |
| 后端架构 | Spring Boot + Spring Cloud Alibaba（4 微服务） |
| 数据库 | MySQL + Redis |
| 模型推理 | navigation-service 集成 ONNX 运行时 |

## 第二部分：开发计划设计

### 2.1 总体阶段划分

```
第1阶段（基础搭建）── 第2阶段（公益核心）── 第3阶段（AI 创新）── 第4阶段（集成+论文）
     Week 1-3           Week 4-8           Week 9-13          Week 14-18
```

### 2.2 详细阶段计划

#### 第1阶段：基础搭建（第1-3周）

**目标**：搭建微服务架构 + Android 项目骨架

| 周次 | 任务 | 产出 |
|------|------|------|
| 第1周 | Nacos + Gateway + MySQL + Redis 环境搭建 | 开发环境就绪 |
| 第2周 | user-service 用户 CRUD + JWT 鉴权 | 用户 API |
| 第3周 | Android 项目初始化、基础 UI 框架、TTS/STT 集成 | 客户端骨架 |

**里程碑 M1：** 开发环境可用，用户注册登录闭环

#### 第2阶段：公益核心（第4-8周）

**目标**：完成公益机构、服务申请、志愿活动、报警等核心业务

| 周次 | 任务 | 产出 |
|------|------|------|
| 第4周 | 公益机构注册 + 审核 + 信息管理 | welfare-service 基础 |
| 第5周 | 公益服务项目管理 + 受护人服务申请 | 服务申请 API |
| 第6周 | 公益活动发布 + 志愿者报名 + 审核 | 志愿 API |
| 第7周 | 监护人绑定 + 位置上报 + 地图查看 | 位置 API |
| 第8周 | 安全报警 + 通知推送 | 报警/通知 API |

**里程碑 M2：** 公益核心业务闭环，受护人可申请服务、触发报警

#### 第3阶段：AI 创新（第9-13周）

**目标**：全景分割导航全链路跑通

| 周次 | 任务 | 产出 |
|------|------|------|
| 第9周 | 全景分割模型选型 + ONNX 导出 + 服务端推理接口 | 模型推理 API |
| 第10周 | Android Camera2 帧采集 + 压缩上传 | 视频帧传输 |
| 第11周 | 空间分析 + 语音引导文本生成 | 导航逻辑 |
| 第12周 | TTS 播报集成 + 帧率优化 | 语音导航闭环 |
| 第13周 | 语音指令识别（呼叫、求助、导航启停） | 语音控制 |

**里程碑 M3（⭐ 核心创新）：** 全景分割导航可实际运行

#### 第4阶段：集成 + 论文（第14-18周）

| 周次 | 任务 | 产出 |
|------|------|------|
| 第14周 | Vue 管理后台（管理员+机构+监护人） | Web 端可用 |
| 第15周 | Android + 后端全链路联调 | 集成测试通过 |
| 第16周 | 边界情况处理、异常流程完善 | 稳定性提升 |
| 第17周 | 撰写毕业设计论文 | 论文初稿 |
| 第18周 | PPT + 演示视频 + 答辩准备 | 答辩准备 |

**里程碑 M4：** 全功能通过，论文提交

### 2.3 纯公益定位说明

相比原版 Sullivan，MINI 版做了以下减法：

| 移除内容 | 理由 |
|---------|------|
| 商户/商业化 | 专注公益，不涉及交易 |
| 商品 + 购物车 + 订单 | 改为公益服务申请，免费 |
| 钱包 + 充值 + 扣费 | 无需金融系统 |
| AI 客服 + LLM 集成 | 聚焦全景分割这一核心 AI 能力 |
| 导盲犬全生命周期 | 可简化为机构提供的一项公益服务 |
| 抽成等级 + 评分系统 | 商业激励机制，不适用于公益场景 |

### 2.4 风险与应对

| 风险 | 影响 | 应对 |
|------|------|------|
| 全景分割实时性不达标 | 核心创新不可用 | 提前选型轻量模型，必要时降帧率 |
| Android 端延迟高 | 用户体验差 | 服务端推理 + 帧压缩 |
| 时间不足 | 无法按时完成 | 核心功能优先，非必要功能可延期 |
