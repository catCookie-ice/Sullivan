# SullivanMINI —— 视障公益服务平台 · 精选用例设计

---

## 核心创新用例 ⭐

### UC-核心 全景分割视觉辅助出行

| 项目 | 内容 |
|------|------|
| **用例名** | 全景分割视觉辅助出行 |
| **参与者** | 受护人（视障人士） |
| **前置条件** | 受护人已登录，已开启出行辅助模式，摄像头正常工作 |
| **后置条件** | 无（实时持续服务） |

**基本流程（每帧处理循环）：**

1. 受护人佩戴的摄像头以固定帧率采集前方实时画面
2. Android 端压缩帧并上传至 `navigation-service`
3. 全景分割模型对画面进行像素级推理：
   - 识别障碍物类别（车辆/行人/台阶/路障/坡道/柱子等）
   - 生成各物体的分割掩码与边界框
4. 空间分析模块计算各障碍物的：
   - 相对距离（通过 bounding box 下沿位置估算）
   - 方位角（左前/正前/右前）
   - 运动趋势（多帧对比判断静止/靠近/远离）
5. 根据当前场景生成语音引导指令：
   - **前方无阻碍** → _"前方安全，可直行"_
   - **前方有障碍** → _"前方约 2 米有台阶，请减速"_
   - **侧方有动态物体** → _"左侧有行人正在靠近"_
   - **路口场景** → _"前方是路口，请确认安全后通过"_
6. 引导指令返回 Android 端，通过 TTS 播报
7. 当前帧处理日志写入 `navigation_log`

**备选流程：**

- **2a** 网络延迟/帧丢失 → 使用上帧结果，提示"信号不稳定"
- **3a** 模型置信度低于阈值 → 生成保守提示（_"前方可能有障碍物，请小心"_）
- **5a** 连续多帧无变化 → 降低播报频率（至少间隔 2 秒），避免重复干扰

**技术指标：**

| 指标 | 目标值 |
|------|--------|
| 帧率 | ≥ 10 FPS |
| 单帧推理延迟 | ≤ 150ms（服务端） |
| 端到端播报延迟 | ≤ 500ms |
| 最小可识别物体 | 30cm × 30cm |

## 一、用户域

### UC-01 监护人绑定受护人

| 项目 | 内容 |
|------|------|
| **参与者** | 监护人（已登录） |
| **前置条件** | 监护人和受护人均已注册 |
| **后置条件** | 绑定关系写入 `guardian_protectee` |

**基本流程：**

1. 监护人输入受护人的 UID 或手机号发起绑定请求
2. 系统校验受护人是否存在
3. 若受护人尚无主监护人 → 将当前监护人设为主监护人
4. 写入 `guardian_protectee` 绑定记录
5. 返回绑定成功

**备选流程：**
- **2a** 受护人不存在 → 返回错误
- **3a** 绑定关系已存在 → 提示重复绑定

---

### UC-02 受护人触发安全报警

| 项目 | 内容 |
|------|------|
| **参与者** | 受护人（已登录） |
| **前置条件** | 受护人已绑定至少一个监护人 |
| **后置条件** | 报警记录写入，通知推送至监护人 |

**基本流程：**

1. 受护人通过语音指令或物理按键触发报警
2. 系统获取受护人实时位置
3. 查询受护人绑定的所有监护人
4. 写入 `alert_log`，推送报警通知（含位置信息）
5. 监护人可在客户端查看受护人实时位置

**备选流程：**
- **3a** 无绑定监护人 → 系统查找附近志愿者并广播求助

---

### UC-03 监护人查看受护人位置

| 项目 | 内容 |
|------|------|
| **参与者** | 监护人（已登录） |
| **前置条件** | 监护人已绑定该受护人 |
| **后置条件** | 无 |

**基本流程：**

1. 监护人打开受护人位置页面
2. 系统从 Redis Geo 读取受护人最新位置
3. 地图上展示受护人当前位置
4. 位置每 10 秒自动刷新

## 二、公益服务域

### UC-04 公益机构注册与审核

| 项目 | 内容 |
|------|------|
| **参与者** | 公益机构管理员、平台管理员 |
| **前置条件** | 机构管理员提交注册信息 |
| **后置条件** | `organization` 新增记录，状态待审核 |

**基本流程：**

1. 机构提交注册信息（名称、类型、简介、联系方式等）
2. 系统写入 `organization`（状态：待审核）
3. 管理员在后台审核机构资料
4. 审核通过 → 状态变更为"已认证"，机构可登录使用
5. 审核不通过 → 状态变更为"已禁用"，注明原因

---

### UC-05 公益机构发布服务项目

| 项目 | 内容 |
|------|------|
| **参与者** | 公益机构（已登录、已认证） |
| **前置条件** | 机构已通过审核 |
| **后置条件** | `welfare_service` 新增记录 |

**基本流程：**

1. 机构填写服务项目信息（名称、描述、名额、配图）
2. 系统校验必填字段
3. 写入 `welfare_service`（状态：开放）
4. 服务项目对受护人可见

**示例项目：** 导盲犬申请、盲杖申领、康复训练报名、心理辅导预约

---

### UC-06 受护人申请公益服务

| 项目 | 内容 |
|------|------|
| **参与者** | 受护人或监护人（已登录） |
| **前置条件** | 服务项目状态为"开放"，有名额 |
| **后置条件** | `service_application` 新增记录 |

**基本流程：**

1. 受护人浏览公益服务项目列表
2. 选择服务项目，填写申请备注
3. 系统校验名额
4. 写入 `service_application`（状态：待审核）
5. 通知机构处理申请
6. 机构审核 → 通过 / 拒绝
7. 通知申请人审核结果
8. 服务完成 → 状态变更为"已完成"

**备选流程：**
- **3a** 名额已满 → 提示用户
- **6a** 机构拒绝 → 填写拒绝原因

## 三、志愿域

### UC-07 机构发布公益活动

| 项目 | 内容 |
|------|------|
| **参与者** | 公益机构（已登录） |
| **前置条件** | 机构已通过认证 |
| **后置条件** | `volunteer_activity` 新增记录 |

**基本流程：**

1. 机构填写活动信息（标题、描述、地点、时间、人数上限）
2. 系统创建活动，状态为"招募中"
3. 到达开始时间 → 状态自动变为"进行中"
4. 到达结束时间 → 状态变为"已结束"

---

### UC-08 志愿者报名活动

| 项目 | 内容 |
|------|------|
| **参与者** | 志愿者（已登录） |
| **前置条件** | 活动状态为"招募中"，未报满 |
| **后置条件** | `volunteer_enrollment` 新增记录 |

**基本流程：**

1. 志愿者浏览活动列表，点击报名
2. 系统校验是否已报名、是否已满
3. 写入 `volunteer_enrollment`（状态：待审核）
4. 机构审核 → 通过 / 拒绝
5. 审核结果通知志愿者

## 四、管理域

### UC-09 运营数据总览

| 项目 | 内容 |
|------|------|
| **参与者** | 管理员（已登录） |
| **前置条件** | 系统中有业务数据 |
| **后置条件** | 无 |

**基本流程：**

1. 管理员登录后台，进入 Dashboard
2. 系统展示统计看板：
   - 用户总数（受护人 / 监护人 / 志愿者）
   - 公益机构数量
   - 本月服务申请数
   - 本月报警次数
   - 热门服务项目 Top 5
   - 活跃志愿者 Top 5
