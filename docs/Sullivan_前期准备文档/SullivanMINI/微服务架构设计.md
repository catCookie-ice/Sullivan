# SullivanMINI —— 视障公益服务平台 · 微服务架构设计

---

## 核心创新：全景分割视觉辅助出行

通过受护人端摄像头实时采集画面，**全景分割模型**对画面中的障碍物（车辆、行人、路障、台阶等）进行像素级识别与分割，结合**空间分析**与**语音合成**，以自然语言实时指导视障人士安全出行。

**技术流程：**

```
摄像头帧采集 → 全景分割 → 障碍物空间分析 → 语音提示生成 → TTS 音频播报
```

**典型提示示例：**
- _"前方 2 米处有台阶，请小心抬脚"_
- _"左侧有行人正在靠近"_
- _"前方道路畅通，可继续直行"_

## 一、微服务划分

### 1. API 网关 — `api-gateway`

| 职责 | 说明 |
|------|------|
| 统一入口 | 所有客户端请求的统一接入点 |
| 路由转发 | 根据请求路径分发到对应微服务 |
| 认证鉴权 | 校验 JWT Token，白名单路径放行 |
| 限流 | 接口限流，防止滥用 |

### 2. 用户服务 — `user-service`

| 职责 | 说明 |
|------|------|
| 用户注册/登录 | 监护人、受护人、志愿者三类用户账户管理 |
| 用户信息管理 | 用户资料 CRUD |
| 监护-受护绑定 | 绑定关系建立与解除，主监护人设置 |
| Token 签发 | 登录成功颁发 JWT |

**涉及表：** user_base, guardian, protectee, volunteer, guardian_protectee

### 3. 导航服务 — `navigation-service` ⭐

> 本项目核心创新服务，计算密集型，建议独立部署并支持 GPU 加速。

| 职责 | 说明 |
|------|------|
| **全景分割推理** ⭐ | 接收摄像头帧，运行全景分割模型，输出障碍物掩码与类别 |
| **空间分析** ⭐ | 计算障碍物距离、方位角、运动趋势 |
| **语音引导生成** ⭐ | 将空间分析结果转为自然语言引导指令 |
| 语音识别 | 受护人语音指令 → 文本（呼叫、求助、导航控制） |
| 语音合成（TTS） | 导航引导文本 → 音频播报 |
| 模型管理 | 模型版本登记与切换 |

**涉及表：** model_registry, navigation_log

**关键接口：**

```
POST /api/navigation/analyze-frame   ← Android 端上传帧，返回引导指令
POST /api/navigation/voice-command   ← 语音指令识别
GET  /api/navigation/models          ← 获取可用模型列表
```

### 4. 公益服务 — `welfare-service`

纯公益导向的综合服务，覆盖公益机构、公益服务申请、志愿活动、安全报警、通知等。

| 职责 | 说明 |
|------|------|
| 公益机构管理 | 机构注册、资料管理、类型划分 |
| 公益服务项目管理 | 机构发布公益服务项目（导盲犬申请、辅具申领、康复训练等） |
| 服务申请管理 | 受护人提交申请 → 机构处理 → 完成闭环 |
| 志愿活动管理 | 发布公益活动、志愿者报名、审核 |
| 安全报警 | 受护人报警 → 通知监护人 + 广播志愿者 |
| 通知推送 | 报警通知、活动通知、申请结果通知 |

**涉及表：** organization, org_type, welfare_service, service_application, volunteer_activity, volunteer_enrollment, alert_log, notification

### 5. 管理服务 — `admin-service`

| 职责 | 说明 |
|------|------|
| 管理员账户管理 | 管理员 CRUD |
| 运营数据查看 | 用户数、服务申请数、报警统计 |
| 机构入驻审核 | 审核公益机构注册申请 |

**涉及表：** admin_base, admin_type

## 二、服务间依赖关系

```
client (Android / Vue)
      │
      ▼
 api-gateway
      │
      ├──▶ user-service ◀──── (依赖：所有服务 Token 校验)
      ├──▶ navigation-service (独立，仅依赖 Redis 缓存)
      ├──▶ welfare-service ──▶ user-service (查询用户信息)
      └──▶ admin-service
```

- **navigation-service** 是独立计算服务，无服务间同步调用
- **welfare-service** 通过 OpenFeign 调用 user-service 查询用户信息
- 所有服务通过 API 网关统一鉴权

## 三、数据存储策略

| 数据库 | 用途 | 说明 |
|--------|------|------|
| **MySQL** | 所有业务数据 | 每个微服务独享数据库，不跨库 JOIN |
| **Redis** | Token 缓存、位置数据（Geo）、热点缓存 | 高性能读写 |

> 全程不涉及商业交易，无需支付对接和金融级事务保障。服务间使用同步 Feign 调用 + 本地事务保证一致性。

## 四、技术栈

### 4.1 客户端

| 终端 | 技术选型 | 说明 |
|------|---------|------|
| **视障人士 Android 端** ⭐ | Kotlin + Camera2 + TTS/STT | 主客户端，聚焦无障碍体验 |
| **管理 Web 端** | Vue 3 + Element Plus + ECharts | 管理员 + 公益机构共用 |

### 4.2 服务端

| 分层 | 技术 | 说明 |
|------|------|------|
| 服务框架 | Spring Boot 3.x + Spring Cloud Alibaba | 微服务基础 |
| 注册/配置 | Nacos | 注册中心 + 配置中心 |
| API 网关 | Spring Cloud Gateway | 路由、鉴权、限流 |
| 远程调用 | OpenFeign + LoadBalancer | 服务间调用 |
| 关系数据库 | MySQL 8.x + MyBatis-Plus | 持久层 |
| 缓存 | Redis | Token 缓存 + 位置 Geo |
| 对象存储 | MinIO | 服务图片、用户头像 |
| 模型推理 | ONNX Runtime | 全景分割模型推理 |
| 认证 | JWT + Spring Security | Token 认证 |
| 文档 | Knife4j (Swagger) | API 文档 |

### 4.3 Android 端关键技术

| 能力 | 技术方案 |
|------|---------|
| 摄像头采集 | Camera2 API |
| 语音识别 | Android SpeechRecognizer |
| 语音播报 | TextToSpeech API |
| 无障碍 | TalkBack + AccessibilityService |
| 地图 | 高德地图 SDK |
| 网络 | Retrofit + OkHttp |
| 视频流传输 | OkHttp 帧上传 |
