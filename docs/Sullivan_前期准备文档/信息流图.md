## 二、核心业务信息流详解

### 2.1 ⭐ 核心创新：全景分割视觉辅助出行

```mermaid
sequenceDiagram
    participant Client as 视障人士客户端
    participant GW as API Gateway
    participant MS as model-service
    participant NS as notification-service
    participant DB as model_usage_log

    loop 每帧处理（≥15FPS）
        Client->>Client: 摄像头采集帧
        Client->>GW: 发送帧数据
        GW->>MS: 推理请求
        MS->>MS: ① 全景分割推理<br/>(yolov8-seg)
        MS->>MS: ② 空间分析<br/>(距离/方位/运动)
        MS->>MS: ③ 生成语音引导文本
        MS-->>GW: 返回引导指令
        GW-->>Client: 返回引导文本
        Client->>Client: TTS 播报
        MS->>DB: 记录调用消耗
    end
```

---

### 2.2 AI客服对话 + 实时扣费

```mermaid
sequenceDiagram
    participant User as 用户
    participant CS as chat-service
    participant MOD as model-service
    participant MCH as merchant-service
    participant DB as MySQL/MongoDB

    User->>CS: 发送消息
    CS->>MCH: 校验AI客服配置<br/>余额 / 日限额 / 时间段
    MCH-->>CS: 校验通过
    CS->>MOD: LLM推理请求
    MOD-->>CS: 返回回复内容
    CS->>MCH: 实时扣费<br/>(wallet_transaction)
    MCH->>MCH: 扣除 ai_wallet
    CS->>DB: 保存消息 (MongoDB)
    CS->>DB: 记录 model_usage_log (MySQL)
    CS-->>User: 推送AI回复
```

---

### 2.3 用户下单 → 评价 → 商户评分

```mermaid
sequenceDiagram
    participant U as 用户
    participant COM as commerce-service
    participant MER as merchant-service

    U->>COM: 提交订单
    COM->>MER: 校验库存 / 查询商品
    COM->>U: 返回订单
    U->>COM: 支付（对接第三方）
    COM->>COM: 扣库存

    Note over U,COM: 收货后
    U->>COM: 商品评价 + 评分 (1~5)
    COM->>COM: 写入 product_review

    U->>COM: 商户评分 (0.0~5.0)
    COM->>COM: 写入 merchant_rating<br/>(覆盖式)

    Note over MER: 每月定时
    MER->>COM: 拉取商户评分均值
    MER->>MER: 匹配 commission_tier
    MER->>MER: 更新抽成等级
```

---

### 2.4 志愿活动发布 → 报名 → 活动群

```mermaid
sequenceDiagram
    participant Org as 机构
    participant Vol as 志愿者
    participant VS as volunteer-service
    participant CHS as chat-service
    participant DB as MySQL/MongoDB

    Org->>VS: 发布活动
    VS->>DB: 写入 volunteer_activity
    Note over VS: 活动开始 → 状态变更为"进行中"

    Vol->>VS: 报名活动
    VS->>VS: 写入 volunteer_enrollment
    Org->>VS: 审核通过

    Note over VS: 活动结束
    VS->>VS: 状态 → "已结束"
    VS->>CHS: 创建活动群
    CHS->>DB: 写入 conversations (type=1)
    CHS->>CHS: 自动将所有通过者加入群聊
    Vol->>CHS: 在群中聊天

    Note over CHS: 活动结束后
    CHS->>CHS: 自动关闭群聊<br/>(status=1)
```

### 2.5 安全报警 → 通知监护人

```mermaid
sequenceDiagram
    participant P as 受护人客户端
    participant NS as notification-service
    participant US as user-service
    participant LS as location-service

    P->>P: 语音指令/按键触发报警
    P->>NS: 发送报警请求
    NS->>US: 查询绑定的监护人列表
    US-->>NS: 返回监护人信息
    NS->>LS: 获取受护人实时位置
    LS-->>NS: 返回位置数据
    NS->>P: 推送报警至所有监护人客户端
    NS->>NS: 短信/电话备用通知
```

## 三、数据存储映射

| 业务数据 | 存储位置 | 读写模式 | 说明 |
|---------|---------|---------|------|
| 用户账户/资料 | MySQL | 频繁读写 | 关系型，ACID |
| 商户/机构/商品 | MySQL | 频繁读写 | 关系型，事务保证 |
| 订单/交易流水 | MySQL | 频繁写入 + 查询 | 事务核心 |
| 模型调用记录 | MySQL | 追加写入 + 统计分析 | 定时归档 |
| 钱包流水 | MySQL | 顺序写入 + 实时查询 | 资金安全要求高 |
| 会话/消息 | MongoDB | 高并发写入 + 按会话查询 | 文档模型，无 schema 约束 |
| 通知记录 | MongoDB | 写入 + 按接收方拉取 | 结构灵活，read_by 数组 |
| 会话缓存 | Redis | 高速读写 | Token 缓存 |
| 位置数据 | Redis Geo | 写入 + 地理范围查询 | 就近匹配 |
| 商品图片 | 对象存储 (OSS/MinIO) | 上传 + CDN 分发 | 静态文件 |
