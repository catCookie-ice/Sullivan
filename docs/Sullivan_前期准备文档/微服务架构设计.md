# Sullivan —— 视障服务连接平台 · 微服务架构设计

> 基于 BS.md 业务需求，划分为以下微服务

---

## 核心创新功能：全景分割视觉辅助出行

通过受护人端摄像头实时采集画面，**全景分割模型** 对画面中的障碍物（车辆、行人、路障、台阶等）进行像素级识别与分割，结合 **语音合成** 以自然语言指导视障人士安全出行。

**技术流程：**

```
摄像头帧采集 → 全景分割(yolov8-seg) → 障碍物空间分析 → 语音提示生成 → 音频播报
```

**典型提示示例：**
- _"前方 2 米处有台阶，请小心抬脚"_
- _"左侧有行人正在靠近"_
- _"前方道路畅通，可继续直行"_

核心创新贯穿以下微服务协作：`model-service`（核心推理）、`location-service`（环境上下文）、`notification-service`（语音播报）。

## 一、微服务划分

### 1. API 网关 — `api-gateway`

| 职责 | 说明 |
|------|------|
| 统一入口 | 所有客户端请求的统一接入点 |
| 路由转发 | 根据请求路径分发到对应微服务 |
| 认证鉴权 | 校验 JWT Token，白名单路径放行 |
| 限流熔断 | 接口限流、服务熔断、降级 |
| 日志记录 | 统一请求日志与 traceId 追踪 |

### 2. 用户服务 — `user-service`

| 职责 | 说明 |
|------|------|
| 用户注册/登录 | 监护人、受护人、志愿者三类用户账户管理 |
| 用户信息管理 | 监护人表、受护人表、志愿者表的 CRUD |
| 监护-受护绑定 | 绑定关系建立与解除 |
| Token 签发 | 登录成功颁发 JWT |

**涉及表（MySQL）：** user_base, guardian, protectee, volunteer, guardian_protectee

### 3. 商户/机构服务 — `merchant-service`

| 职责 | 说明 |
|------|------|
| 商户/机构注册登录 | 基表账户管理、认证截止日期管理 |
| 商户信息管理 | 商户资料、评分统计、抽成等级计算与更新 |
| 机构信息管理 | 机构资料、认证状态 |
| 商品管理 | 商品 CRUD、上架/下架（含定时下架） |
| 导盲犬管理 | 导盲犬 CRUD、状态流转 |
| 服务人员管理 | 客服和活动指导账号创建（商户/机构自行创建） |
| AI客服管理 | AI客服配置（人设、预设、模型、工作时间段、日限额） |
| 钱包管理 | 充值、实时扣费、日终对账、钱包流水查询 |

**涉及表（MySQL）：** merchant_org_type, merchant_org_base, merchant, organization, product, guide_dog, service_staff, ai_staff_config, ai_staff_usage, recharge_record, wallet_transaction, commission_tier, model_category, model_registry, model_preset, model_usage_log

**涉及集合（MongoDB）：** conversations（客服对话）

### 4. 商业服务 — `commerce-service`

| 职责 | 说明 |
|------|------|
| 订单管理 | 创建订单、订单状态流转 |
| 支付对接 | 调用支付接口，处理支付回调 |
| 退款处理 | 申请退款、审核退款 |
| 商品评价 | 初次评价、追评（需验证购买记录） |
| 商户评分 | 购买过该商户的用户可评分（覆盖式） |

**涉及表（MySQL）：** order, order_item, product_review, merchant_rating

### 5. 志愿活动服务 — `volunteer-service`

| 职责 | 说明 |
|------|------|
| 活动管理 | 机构发布/管理志愿活动 |
| 报名审核 | 志愿者报名，机构审核 |
| 活动状态管理 | 招募中 → 进行中 → 已结束 |
| 活动群管理 | 活动群自动创建与自动关闭（结束后） |

**涉及集合（MongoDB）：** conversations（活动群）, messages

### 6. 管理/运营服务 — `admin-service`

| 职责 | 说明 |
|------|------|
| 管理员账户管理 | 管理员 CRUD、类型分配 |
| 权限管理 | 额外权限的授予与回收 |
| 运营数据查看 | 用户数、订单数、商品数等统计 |
| 全局审核 | 商户/机构认证审核、爱心商家认证 |
| 通知发布 | 系统公告、邮件发送 |

**涉及表（MySQL）：** admin_type, admin_base, extra_permission, admin_extra_perm

**涉及集合（MongoDB）：** notifications

### 7. 模型服务 — `model-service`

| 职责 | 说明 |
|------|------|
| 模型登记 | 统一管理所有业务模型（AI客服、全景分割、语音等） |
| **全景分割** ⭐ | **受护人摄像头实时画面分割，识别路障、行人、台阶、坡道等，输出掩码与类别** |
| **空间分析** ⭐ | **基于分割结果计算障碍物距离、方位、移动速度，生成结构化环境描述** |
| **语音引导** ⭐ | **将环境描述转为自然语言指令，调用语音合成播报给受护人** |
| 语音识别 | 受护人语音指令 → 文本（呼叫监护人、求助等） |
| 语音提示 | 系统主动语音播报（报警、提醒等） |
| AI客服推理 | 调用 LLM 生成客服回复 |
| 消耗记录 | 每次调用写入调用记录（内部模型不计费） |

> 该服务为计算密集型，全景分割需实时处理视频流，建议独立部署并支持 GPU 加速。

**涉及表（MySQL）：** model_registry, model_category, model_preset, model_usage_log

### 8. 通知/通讯服务 — `notification-service`

| 职责 | 说明 |
|------|------|
| 安全报警 | 受护人触发报警 → 通知监护人 |
| 求助播报 | 受护人求助 → 广播给附近志愿者 |
| 视频通话 | 监护人与受护人实时视频（信令 + 媒体转发） |
| 消息推送 | 站内通知、推送通知 |

### 9. 位置服务 — `location-service`

| 职责 | 说明 |
|------|------|
| 位置上报 | 受护人实时位置接收 |
| 位置查询 | 监护人查看受护人位置 |
| 就近匹配 | 寻找受护人附近的志愿者（地理围栏） |

### 10. 聊天服务 — `chat-service`

| 职责 | 说明 |
|------|------|
| 会话管理 | 客服对话和活动群的创建、关闭 |
| 消息收发 | 消息发送、按会话拉取消息列表 |
| 活动群自动关闭 | 活动结束后定时关闭关联群聊 |

**涉及集合（MongoDB）：** conversations, messages

## 二、服务间依赖关系

```
client
  │
  ▼
api-gateway
  │
  ├──▶ user-service ◀──── (被所有服务依赖，Token 校验)
  ├──▶ merchant-service
  ├──▶ commerce-service ──▶ merchant-service (查询商品、商户)
  │                        └── user-service (查询用户)
  ├──▶ volunteer-service ──▶ merchant-service (查询机构)
  ├──▶ admin-service
  ├──▶ model-service ──────▶ merchant-service (查询AI客服配置)
  ├──▶ chat-service ───────▶ merchant-service (客服身份校验)
  │                        └── user-service (用户身份校验)
  ├──▶ notification-service ──▶ user-service (查联系人)
  │                          └── location-service (查附近志愿者)
  └──▶ location-service
```

## 三、数据库策略

| 数据库 | 存储域 | 说明 |
|--------|--------|------|
| **MySQL 8.x** | 用户、商户/机构、交易、志愿活动、管理、模型登记 | 每个微服务独享数据库，不跨库 JOIN |
| **MongoDB** | 聊天记录、通知 | 文档模型，高写入性能 |
| **Redis** | 会话缓存、商品缓存、位置（Geo） | 热点数据缓存 |

- 每个微服务独享数据库（按业务域拆分），通过服务间 API 跨域查询，不跨库 JOIN
- 公共基础数据（如类型对照表）在每个需要的服务中冗余一份 + 缓存
- 异步场景（订单 → 通知、活动结束 → 关群）通过 RabbitMQ 解耦
- 位置数据使用 Redis Geo 结构处理地理查询

## 四、推荐技术栈

### 4.1 客户端

| 终端 | 技术选型 | 关键考量 |
|------|---------|---------|
| **视障人士移动客户端** ⭐ | **Android Native（Kotlin）** | 原生 TTS/STT API、Camera2 视频采集、无障碍服务（TalkBack）、高对比度大字体 UI、手势+语音双交互 |
| **监护人移动客户端** | Flutter | 跨平台一套代码，地图/视频通话插件生态成熟 |
| **志愿者 Web 端** | Vue 3 + Element Plus | 响应式设计，桌面优先 |
| **商家/机构 Web 端** | Vue 3 + Element Plus + ECharts | 管理后台 + 数据看板 |
| **客服/活动指导 移动端** | Flutter / H5 + 移动适配 | 轻量级，消息通讯为主 |
| **管理员 Web 端** | Vue 3 + Element Plus + ECharts | 完整后台管理 + 运营统计 |

> **视障人士客户端** 选择 Android Native 的原因：系统级无障碍服务依赖（TalkBack、随选朗读）、TTS/STT 低延迟调用、Camera2 直接对接全景分割视频流。跨平台方案（Flutter/RN）在深度无障碍支持上仍有缺口。

### 4.2 服务端

| 分层 | 技术 | 说明 |
|------|------|------|
| **服务框架** | Spring Boot 3.x + Spring Cloud Alibaba | 微服务基础框架 |
| **服务注册/配置** | Nacos | 注册中心 + 配置中心 |
| **API 网关** | Spring Cloud Gateway | 路由、鉴权、限流 |
| **远程调用** | OpenFeign + LoadBalancer | 服务间同步调用 |
| **异步通信** | RabbitMQ | 服务间异步消息 |
| **分布式事务** | Seata | AT 模式，保证跨服务事务一致性 |
| **关系数据库** | MySQL 8.x + MyBatis-Plus | 关系型数据存储与 ORM |
| **文档数据库** | MongoDB | 聊天消息、通知存储 |
| **缓存** | Redis | 会话缓存、商品缓存、位置 Geo 查询 |
| **对象存储** | MinIO 或 阿里云 OSS | 商品图片、用户头像等 |
| **认证** | JWT + Spring Security | Token 认证与授权 |
| **文档** | Knife4j (Swagger) | API 文档聚合 |
| **部署** | Docker + Docker Compose | 容器化部署 |
| **监控** | Spring Boot Admin + Prometheus | 服务监控 |

### 4.3 客户端技术栈详解

| 能力 | 视障人士客户端（Android） | 其他客户端（Flutter / Vue） |
|------|--------------------------|---------------------------|
| **语音输入** | Android SpeechRecognizer | Web Speech API / flutter_speech |
| **语音播报** | TextToSpeech API | fluter_tts / Web Speech |
| **无障碍** | TalkBack / AccessibilityService | 有限支持 |
| **摄像头** | Camera2 + MLKit 预处理 | image_picker 等 |
| **视频通话** | WebRTC (native) | WebRTC (plugin) |
| **地图** | 高德/百度 SDK | 高德/百度 各端插件 |
| **消息推送** | 极光推送 / 个推 | — |
