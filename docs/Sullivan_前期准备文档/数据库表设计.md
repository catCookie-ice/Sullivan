# Sullivan —— 视障服务连接平台 · 数据库表设计

> 基于 BS.md 业务描述整理

---

## 存储策略

| 数据库 | 存储域 |
|--------|--------|
| **MySQL** | 用户域、商户/机构域、交易域、志愿活动域、管理域、服务人员表、关联关系表 |
| **MongoDB** | 聊天域（会话、消息）、通知域（通知记录） |

> 会话和通知采用 MongoDB，利用其文档灵活、写入高效的特性处理高并发的聊天消息和结构多变的通知。

## 一、用户域

### 1.1 用户基表 — `user_base`

| 列名 | 类型 | 约束 | 说明 |
|------|------|------|------|
| uid | BIGINT | **PK**, NOT NULL | 用户唯一ID |
| account | VARCHAR(50) | **NOT NULL**, UNIQUE | 登录账户 |
| password | VARCHAR(255) | **NOT NULL** | 登录密码（哈希） |
| phone | VARCHAR(20) | NULL | 手机号 |
| type | TINYINT | **NOT NULL** | 用户类型（0:监护人, 1:受护人, 2:志愿者） |
| created_at | DATETIME | **NOT NULL** | 注册时间 |
| updated_at | DATETIME | **NOT NULL** | 更新时间 |

> 仅三类用户，无需类型对照表。各扩展表通过 uid 与基表形成 **1:1** 关系。

### 1.2 监护人表 — `guardian`

| 列名 | 类型 | 约束 | 说明 |
|------|------|------|------|
| uid | BIGINT | **PK, FK → user_base.uid**, NOT NULL | 监护人UID |

| emergency_contact | VARCHAR(20) | NULL | 紧急联系电话 |

### 1.3 受护人表 — `protectee`

| 列名 | 类型 | 约束 | 说明 |
|------|------|------|------|
| uid | BIGINT | **PK, FK → user_base.uid**, NOT NULL | 受护人UID |
| name | VARCHAR(50) | **NOT NULL** | 姓名 |
| birth_date | DATE | NULL | 出生日期 |

> `primary_guardian_uid` 保证每个受护人至少在数据库层面有一个绑定的主监护人；额外的监护人通过 `guardian_protectee` 关联表添加。

### 1.4 志愿者表 — `volunteer`

### 2.8 通用模型登记表 — `model_registry`

统一管理所有业务模型，涵盖 AI客服模型、全景分割模型、语音模型等。定价语义根据类别而定：LLM 类为每千 Token 价格，视觉/语音类为每次推理价格。

| 列名 | 类型 | 约束 | 说明 |
|------|------|------|------|
| model_id | INT | **PK**, NOT NULL | 模型编号 |
| model_name | VARCHAR(100) | **NOT NULL** | 模型名称（如：gpt-4o-mini, deepseek-chat, yolov8-seg） |
| category_id | INT | **NOT NULL, FK → model_category.category_id** | 模型职责分类 |
| input_price | DECIMAL(10, 4) | NULL | 输入/推理单价（LLM为每千Token，内部模型为NULL） |
| output_price | DECIMAL(10, 4) | NULL | 输出单价（LLM为每千Token，内部模型为NULL） |
| available_for_merchant | TINYINT | **NOT NULL** DEFAULT 0 | 是否可供商家选用（0:否, 1:是） |
| status | TINYINT | **NOT NULL** DEFAULT 1 | 状态（0:下架, 1:上架） |
| created_at | DATETIME | **NOT NULL** | 创建时间 |

> `input_price / output_price` 为 NULL 表示内部免费模型（如全景分割、语音处理），不计费。

### 2.9 模型预设人设表 — `model_preset`

仅适用于 AI客服类模型（`category_id` 对应 AI客服），保存预设人设提示词。

| 列名 | 类型 | 约束 | 说明 |
|------|------|------|------|
| preset_id | INT | **PK**, NOT NULL | 预设ID |
| model_id | INT | **NOT NULL, FK → model_registry.model_id** | 所属模型 |
| preset_name | VARCHAR(100) | **NOT NULL** | 预设名称（如：专业导购、耐心解答） |
| preset_content | TEXT | **NOT NULL** | 预设人设提示词内容 |
| created_at | DATETIME | **NOT NULL** | 创建时间 |

### 2.10 模型调用记录表 — `model_usage_log`

记录所有模型的每次调用消耗。AI客服类调用记录对应商家扣费，内部模型调用（全景分割、语音等）记录消耗量用于统计。

| 列名 | 类型 | 约束 | 说明 |
|------|------|------|------|
| log_id | BIGINT | **PK**, NOT NULL | 调用记录ID |
| model_id | INT | **NOT NULL, FK → model_registry.model_id** | 使用的模型 |
| caller_type | TINYINT | **NOT NULL** | 调用职责（0:AI客服, 1:行路辅助, 2:语音指令, 3:语音提示） |
| caller_ref_id | BIGINT | NULL | 调用方参考ID（AI客服时为 service_staff.staff_id，其他为受护人 uid） |
| input_units | BIGINT | **NOT NULL** | 输入量（LLM为Token数，视觉为帧/次） |
| output_units | BIGINT | **NOT NULL** | 输出量（LLM为Token数，视觉为0） |
| cost | DECIMAL(10, 4) | **NOT NULL** DEFAULT 0 | 消耗金额（内部模型为0） |
| called_at | DATETIME | **NOT NULL** | 调用时间 |

> **索引建议**：`{ model_id, called_at }` 支持按模型统计消耗；`{ caller_type, caller_ref_id, called_at }` 支持按调用方查询。

### 2.11 充值记录表 — `recharge_record`

| 列名 | 类型 | 约束 | 说明 |
|------|------|------|------|
| record_id | BIGINT | **PK**, NOT NULL | 充值记录ID |
| sid | BIGINT | **NOT NULL, FK → merchant_org_base.sid** | 商户ID |
| amount | DECIMAL(10, 2) | **NOT NULL** | 充值金额 |
| payment_method | VARCHAR(50) | NULL | 支付方式 |
| status | TINYINT | **NOT NULL** | 状态（0:待支付, 1:已支付, 2:已退款） |
| created_at | DATETIME | **NOT NULL** | 创建时间 |
| paid_at | DATETIME | NULL | 支付时间 |

### 2.12 钱包流水表 — `wallet_transaction`

记录商户钱包每一笔资金变动，包括充值、AI客服实时扣费、日结调整等。**每次 AI 客服回复后立即扣减余额**（余额不足则拒绝服务），避免商户次日注销导致坏账。

| 列名 | 类型 | 约束 | 说明 |
|------|------|------|------|
| tx_id | BIGINT | **PK**, NOT NULL | 流水ID |
| sid | BIGINT | **NOT NULL, FK → merchant_org_base.sid** | 商户ID |
| type | TINYINT | **NOT NULL** | 类型（0:充值, 1:AI客服扣费, 2:退款, 3:日结调整） |
| amount | DECIMAL(10, 2) | **NOT NULL** | 变动金额（正数=收入, 负数=支出） |
| balance_before | DECIMAL(10, 2) | **NOT NULL** | 变动前余额 |
| balance_after | DECIMAL(10, 2) | **NOT NULL** | 变动后余额 |
| reference_type | VARCHAR(50) | NULL | 关联单据类型（recharge / model_usage / daily_settle） |
| reference_id | BIGINT | NULL | 关联单据ID |
| remark | VARCHAR(255) | NULL | 备注 |
| created_at | DATETIME | **NOT NULL** | 发生时间 |

> **扣费流程**：每次AI回复后 → 写入 `model_usage_log` → 实时扣除 `ai_wallet`（余额不足则拒答）→ 写入 `wallet_transaction`（type=1）。`ai_staff_usage` 作为每日汇总对账记录，单条流水可与 `model_usage_log.log_id` 通过 `reference_id` 关联。

### 2.13 抽成等级配置表 — `commission_tier`

| 列名 | 类型 | 约束 | 说明 |
|------|------|------|------|
| tier_id | INT | **PK**, NOT NULL | 等级编号 |
| tier_name | VARCHAR(50) | **NOT NULL** | 等级名称（爱心商家、钻石商家、5分商家、4.5分商家…、新注册商家） |
| min_score | DECIMAL(2, 1) | NULL | 最低评分要求（null 表示不限制） |
| max_score | DECIMAL(2, 1) | NULL | 最高评分要求 |
| min_sales_rank | INT | NULL | 销售额排名要求（钻石商家专用） |
| max_sales_rank | INT | NULL | 销售额排名要求 |
| commission_rate | DECIMAL(3, 1) | **NOT NULL** | 平台抽成百分比（最高 2.0%） |

> **等级示例**（采用基准线加减机制，基准线 = 3分）：
>
> 商户评分以 3.0 为基准，每上升一个区间则晋升一级（抽成降低），每下降一个区间则降一级（抽成升高，最高 1.8%）。
>
> | 等级 | 评分范围 | 相对于基准线 | 抽成率 | 最低钱包余额 |
> |------|---------|------------|-------|------------|
> | 爱心商家 | — | 公益认证，不参与评级 | 0% | 不限 |
> | 钻石商家 | — | 月度评分+销售额 TOP N | 0.2% | 不限 |
> | 五星商家 | 4.8 ~ 5.0 | 基准 +1.8 以上 | 0.5% | 50.00 |
> | 四星商家 | 4.0 ~ 4.7 | 基准 +1.0 ~ +1.7 | 0.7% | 100.00 |
> | 三星商家 | 3.0 ~ 3.9 | 基准线 ±0.9 | 1.0% | 200.00 |
> | 二星商家 | 2.0 ~ 2.9 | 基准 -0.1 ~ -1.0 | 1.4% | 350.00 |
> | 一星商家 | 0 ~ 1.9 | 基准 -1.1 以下 | 1.8% | 500.00 |
> | 新注册商家 | — | 注册未满一个月（临时等级） | 0.8% | 300.00 |
>
> 商户评分每月基于当月所有用户评分均值重新计算，抽成等级随之更新。评分越高 → 抽成越低 → 最低钱包余额要求越低。

## 三、订单与商品交易域

### 3.1 订单表 — `order`

| 列名 | 类型 | 约束 | 说明 |
|------|------|------|------|
| oid | BIGINT | **PK**, NOT NULL | 订单ID |
| uid | BIGINT | **NOT NULL, FK → user_base.uid** | 购买者（用户） |
| sid | BIGINT | **NOT NULL, FK → merchant.sid** | 所属商户 |
| total_price | DECIMAL(10, 2) | **NOT NULL** | 订单总价 |
| status | TINYINT | **NOT NULL** | 状态（0:待支付, 1:已支付, 2:已发货, 3:已收货, 4:已退款, …） |
| created_at | DATETIME | **NOT NULL** | 下单时间 |
| paid_at | DATETIME | NULL | 支付时间 |
| shipped_at | DATETIME | NULL | 发货时间 |
| received_at | DATETIME | NULL | 确认收货时间 |

### 3.2 订单明细表 — `order_item`

| 列名 | 类型 | 约束 | 说明 |
|------|------|------|------|
| item_id | BIGINT | **PK**, NOT NULL | 明细ID |
| oid | BIGINT | **NOT NULL, FK → order.oid** | 所属订单（订单 → 明细 1:N） |
| pid | BIGINT | **NOT NULL, FK → product.pid** | 商品ID |
| quantity | INT | **NOT NULL** | 购买数量 |
| unit_price | DECIMAL(10, 2) | **NOT NULL** | 下单时单价（快照） |

### 3.3 商品评价表 — `product_review`

用户购买过该商品后，可评价一次、评分一次（1-5分）、一周后可追评一次。

| 列名 | 类型 | 约束 | 说明 |
|------|------|------|------|
| review_id | BIGINT | **PK**, NOT NULL | 评价ID |
| uid | BIGINT | **NOT NULL, FK → user_base.uid** | 评价用户 |
| pid | BIGINT | **NOT NULL, FK → product.pid** | 被评商品 |
| oid | BIGINT | **NOT NULL, FK → order.oid** | 关联订单（验证购买记录） |
| rating | TINYINT | **NOT NULL** | 评分（1 ~ 5） |
| content | TEXT | NULL | 评价内容 |
| review_type | TINYINT | **NOT NULL** DEFAULT 0 | 类型（0:初次评价, 1:追评） |
| parent_review_id | BIGINT | NULL, **FK → product_review.review_id** | 追评时指向原评价 |
| created_at | DATETIME | **NOT NULL** | 评价时间 |

> **约束**：同一用户对同一商品仅可有一条 `review_type=0` 的评价；追评（`review_type=1`）须在初次评价至少一周后。

### 3.4 商户评分表 — `merchant_rating`

用户在该商户购买过一次后，可对该商户评分（0 ~ 5 分）。商户最终评分每月更新一次，用于计算抽成等级。

| 列名 | 类型 | 约束 | 说明 |
|------|------|------|------|
| rating_id | BIGINT | **PK**, NOT NULL | 评分ID |
| sid | BIGINT | **NOT NULL, FK → merchant.sid** | 被评商户 |
| uid | BIGINT | **NOT NULL, FK → user_base.uid** | 评分用户 |
| rating | DECIMAL(2, 1) | **NOT NULL** | 评分（0.0 ~ 5.0） |
| created_at | DATETIME | **NOT NULL** | 评分时间 |

> **约束**：同一用户对同一商户仅可保留一条评分，再次评分即覆盖。商户月度评分为当月所有评分的均值。

| type_id | INT | **NOT NULL, FK → admin_type.type_id** | 管理员类型 |
| name | VARCHAR(50) | NULL | 姓名 |
| status | TINYINT | **NOT NULL** DEFAULT 1 | 状态 |
| created_at | DATETIME | **NOT NULL** | 创建时间 |

### 5.3 额外权限对照表 — `extra_permission`

| 列名 | 类型 | 约束 | 说明 |
|------|------|------|------|
| perm_id | INT | **PK**, NOT NULL | 权限编号 |
| perm_name | VARCHAR(50) | **NOT NULL** | 权限名称（如：志愿者管理、监/受护人管理、商户管理） |
| description | VARCHAR(255) | NULL | 描述 |

### 5.4 管理员额外权限表 — `admin_extra_perm`

| 列名 | 类型 | 约束 | 说明 |
|------|------|------|------|
| id | BIGINT | **PK**, NOT NULL | 自增ID |
| cid | BIGINT | **NOT NULL, FK → admin_base.cid** | 管理员ID（管理员 → 额外权限 N:M） |
| perm_id | INT | **NOT NULL, FK → extra_permission.perm_id** | 额外权限ID |

> 通过该表实现 N:M 关系：一个管理员可拥有多个额外权限，一个额外权限可被多个管理员拥有。

### 7.1 服务人员表（MySQL）— `service_staff`

客服与活动指导共用一个表，由 `type` 区分。

| 列名 | 类型 | 约束 | 说明 |
|------|------|------|------|
| staff_id | BIGINT | **PK**, NOT NULL | 服务人员ID |

| name | VARCHAR(50) | **NOT NULL** | 姓名/昵称 |

### 7.2 AI客服配置表（MySQL）— `ai_staff_config`

AI客服专属配置，与 `service_staff` 为 **1:1** 关系（仅 `is_ai=1` 的记录有对应配置）。

| 列名 | 类型 | 约束 | 说明 |
|------|------|------|------|

### 7.3 AI客服日结表（MySQL）— `ai_staff_usage`

每日汇总对账记录，记录每个AI客服每日的总消耗。**实际扣费已在每次回复时通过 `wallet_transaction` 实时完成**，此表作为日终对账与统计依据。

| 列名 | 类型 | 约束 | 说明 |
|------|------|------|------|
| usage_id | BIGINT | **PK**, NOT NULL | 消耗记录ID |
| staff_id | BIGINT | **NOT NULL, FK → service_staff.staff_id** | AI客服ID |
| date | DATE | **NOT NULL** | 消耗日期 |
| tokens_used | BIGINT | **NOT NULL** | 消耗 Token 数 |
| cost | DECIMAL(10, 4) | **NOT NULL** | 消耗金额（元） |
| created_at | DATETIME | **NOT NULL** | 记录时间 |

### 7.4 会话集合（MongoDB）— `conversations`

统一记录客服对话（用户 ↔ 客服）和活动群（志愿者群聊），参与人以内嵌数组存储。

```json
{
  "_id": ObjectId,
  "type": 0,            // 0:客服对话, 1:活动群
  "title": "xxx",
  "related_id": 12345,  // type=1 时关联 volunteer_activity.vid
  "status": 0,           // 0:进行中, 1:已关闭
  "participants": [
    { "participant_type": 0, "participant_id": 1001, "joined_at": ISODate },
    { "participant_type": 1, "participant_id": 5001, "joined_at": ISODate }
  ],
  "created_at": ISODate,
  "closed_at": null
}
```

| 字段 | 类型 | 说明 |
|------|------|------|
| _id | ObjectId | 会话ID |
| type | int | 0:客服对话, 1:活动群 |
| title | string | 会话标题（活动群自动取活动标题） |
| related_id | long / null | type=1 时 → volunteer_activity.vid |
| status | int | 0:进行中, 1:已关闭 |
| participants | array | 参与人数组，内嵌 `{ participant_type, participant_id, joined_at }` |
| created_at | Date | 创建时间 |
| closed_at | Date / null | 关闭时间 |

> 活动群与志愿活动 **1:1** 关联，活动结束后由定时任务自动关闭群聊。

### 7.5 消息集合（MongoDB）— `messages`

```json
{
  "_id": ObjectId,
  "conv_id": ObjectId,
  "sender_type": 0,     // 0:用户, 1:客服/指导
  "sender_id": 1001,    // user_base.uid 或 service_staff.staff_id
  "content": "你好，有什么可以帮您？",
  "msg_type": 0,        // 0:文本, 1:图片, 2:语音
  "sent_at": ISODate
}
```

| 字段 | 类型 | 说明 |
|------|------|------|
| _id | ObjectId | 消息ID |
| conv_id | ObjectId | 所属会话ID，**需建索引** |
| sender_type | int | 0:用户, 1:客服/指导 |
| sender_id | long | 发送者ID |
| content | string | 消息内容 |
| msg_type | int | 0:文本, 1:图片, 2:语音 |
| sent_at | Date | 发送时间 |

> **索引建议**：`{ conv_id: 1, sent_at: 1 }` 复合索引，支持按会话拉取消息。

## 八、通知域（MongoDB）

通知类型直接在应用层以枚举管理，不单建集合。已读状态通过 `read_by` 数组追踪每个用户的阅读情况，支持全体发送和指定发送。

### 8.1 通知集合 — `notifications`

```json
{
  "_id": ObjectId,
  "type": "system_announcement",   // 枚举: system_announcement, email, review_result
  "title": "系统维护通知",
  "content": "系统将于...",
  "sender": {
    "sender_type": 0,    // 0:管理员, 1:机构
    "sender_id": 1       // admin_base.cid 或 merchant_org_base.sid
  },
  "receiver_type": 0,    // 0:全体用户, 1:指定用户, 2:指定商户/机构
  "receiver_id": null,   // receiver_type=0 时为 null
  "read_by": [ 1001, 1002 ],  // 已读用户 UID 列表
  "created_at": ISODate
}
```

| 字段 | 类型 | 说明 |
|------|------|------|
| _id | ObjectId | 通知ID |
| type | string | 通知类型枚举（system_announcement / email / review_result） |
| title | string | 通知标题 |
| content | string | 通知内容 |
| sender | object | `{ sender_type, sender_id }` 发送者信息 |
| receiver_type | int | 0:全体, 1:指定用户, 2:指定商户/机构 |
| receiver_id | long / null | 接收方ID，全体时 null |
| read_by | array[long] | 已读用户 UID 列表，用于计算未读数 |
| created_at | Date | 发送时间 |

> **索引建议**：`{ receiver_type: 1, receiver_id: 1, created_at: -1 }` 支持按接收方拉取通知列表。
