# SullivanMINI 角色权限与数据范围

**文档版本:** v1.0  
**基线日期:** 2026-07-26  
**安全模型:** RBAC + 行级数据权限 + 资源状态约束

## 1. 授权原则

1. 默认拒绝。没有明确授予的功能和数据范围均返回 `403`。
2. 服务端强制。客户端菜单、路由守卫和按钮隐藏只改善体验，不能替代 API 鉴权。
3. 主体可信。`principal_id`、`principal_type` 和角色取自已验证 JWT，不接受请求体覆盖。
4. 逐层收窄。一次操作必须同时通过账号状态、角色权限、行级范围、资源状态和字段级规则。
5. 最小披露。列表查询先施加数据范围再分页，不能先查全量后在客户端过滤。
6. 关系实时。监护权限只来自当前 `ACTIVE` 绑定；终止后立即失效。
7. 关联校验。写入关联 ID 前校验对象、角色和状态，读取时仍需重新鉴权。
8. 管理员受限。管理员不因角色自动获得实时位置、密码、令牌或导航原始帧访问权。

## 2. 客户端入口

| 角色 | Android | 响应式 Web | 主要入口 |
|---|---|---|---|
| `PROTECTEE` | 登录后使用 | 否 | 导航、报警、其它绑定确认、服务申请、通知 |
| `GUARDIAN` | 是 | 是 | 绑定管理、受护人位置、报警、代申请、通知 |
| `VOLUNTEER` | 是 | 是 | 可服务状态、活动报名、附近求助、通知；可与监护人并存 |
| `ORGANIZATION` | 否 | 是 | 机构资料、服务项目、服务申请、活动、报名审核 |
| `ADMIN` | 否 | 是 | 机构审核、用户治理、统计、管理员管理 |

自然人的角色由 `user_role` 关系表维护。自然人注册时至少拥有 `GUARDIAN` 或 `VOLUNTEER` 一个角色；监护人兼任志愿者时同时拥有两个角色，接口按当前角色权限集合判断。

## 3. 功能权限矩阵

符号: `C` 创建，`R` 读取，`U` 修改/处理，`X` 取消/终止，`-` 无权限。实际数据行范围见第 4 节。

| 资源/操作 | 受护人 | 监护人 | 志愿者 | 机构 | 管理员 |
|---|---|---|---|---|---|
| 自身账号和资料 | `R/U` | `R/U` | `R/U` | `R/U` | `R/U` |
| 绑定请求 | `R/U` 确认拒绝 | `C/R/X` | `-` | `-` | `R` 审计 |
| 生效绑定 | `R/X` | `R/X` | `-` | `-` | `R` 审计 |
| 受护人位置上报 | `C/U` 自身 | `-` | `-` | `-` | `-` |
| 受护人位置查看 | `R` 自身 | `R` 已绑定 | `-` | `-` | `-` |
| 导航会话/帧 | `C/R/U` 自身 | `-` | `-` | `-` | 聚合统计，不读原始帧 |
| 报警 | `C/R/U` 自身 | `R/U` 已投递 | `R/U` 已投递 | `-` | `R` 治理权限 |
| 自身通知 | `R/U` | `R/U` | `R/U` | `R/U` | `R/U` |
| 机构注册/资料 | `R` 已认证公开信息 | `R` 已认证公开信息 | `R` 已认证公开信息 | `C/R/U` 自身 | `R/U` 审核治理 |
| 公益服务项目 | `R` 开放 | `R` 开放 | `R` 开放 | `C/R/U/X` 自身 | `R/U` 治理 |
| 服务申请 | `C/R/X` 自身 | `C/R/X` 代申请 | `-` | `R/U` 自有项目 | `R/U` 治理 |
| 公益活动 | `R` 公开 | `R` 公开 | `R` 公开 | `C/R/U/X` 自身 | `R/U` 治理 |
| 活动报名 | `-` | `-` | `C/R/X` 自身 | `R/U` 自有活动 | `R/U` 治理 |
| 志愿者状态/位置 | `-` | `-` | `R/U` 自身 | `-` | 仅治理状态，不读实时位置 |
| 运营统计 | `-` | `-` | `-` | `R` 自身业务汇总 | `R` 有统计权限 |
| 管理员账号/授权 | `-` | `-` | `-` | `-` | `SUPER_ADMIN C/R/U`；`HR_ADMIN R` |
| 管理员注册码 | `-` | `-` | `-` | `-` | `SUPER_ADMIN/HR_ADMIN C/R` |
| 审计日志 | `-` | `-` | `-` | `-` | `R` 有审计权限 |

## 4. 行级数据权限

### 4.1 自然人账号与资料

| 主体 | 可访问行 | 必须查询条件 |
|---|---|---|
| 自然人 | 自己的账号及角色扩展资料 | `uid = token.subject_id` |
| 监护人 | 被绑定受护人的必要公开资料 | 存在 `(guardian_uid=subject AND protectee_uid=target AND status='ACTIVE')` |
| 机构 | 申请或报名处理中必要的姓名和联系方式 | 业务记录属于本机构，且字段白名单 |
| 管理员 | 权限覆盖的用户；敏感字段脱敏 | 具备 `USER_READ` 或治理权限 |

任何角色均不得通过普通资料接口读取密码哈希、刷新令牌、完整审计上下文或其他用户的绑定列表。

### 4.2 绑定关系

- 监护人可读 `guardian_uid = subject` 的请求和关系。
- 受护人可读 `protectee_uid = subject` 的请求和关系。
- 只有 `PENDING` 请求的目标受护人可确认或拒绝。
- 只有发起监护人可取消 `PENDING` 请求。
- `ACTIVE` 关系中的任一方可解除；其他自然人无权读取。
- 管理员只在投诉、审计或治理场景读取，不得替受护人确认绑定。

### 4.3 位置

- 受护人只能写 `protectee_uid = subject` 的位置。
- 监护人读取目标位置时，Java 应用必须实时确认 `ACTIVE` 绑定；缓存命中也不能跳过关系版本校验。
- 志愿者只能写自己的位置和可服务状态，不能查询其他志愿者坐标。
- Java 报警匹配任务可查询符合条件的志愿者，但只固化接收人 ID，不向业务用户返回候选人坐标列表。
- 管理员统计只可使用区域化或聚合位置，不可默认读取实时点位。

### 4.4 公益项目与申请

- 所有人可读取已认证机构的 `OPEN` 项目公开字段。
- 机构可读取和修改 `organization_id = subject` 的项目。
- 受护人可读取 `beneficiary_protectee_uid = subject` 的申请。
- 监护人可读取自己提交的申请，以及当前仍与受益人存在 `ACTIVE` 绑定的代申请详情。
- 机构仅可处理其项目产生的申请，条件必须同时校验 `application.organization_id = subject` 和项目归属。
- 管理员治理查询必须带权限和审计原因，不得修改申请人为另一自然人。

### 4.5 活动与报名

- 公开活动只展示非敏感活动字段，不展示报名者清单。
- 志愿者只可读取和取消 `volunteer_uid = subject` 的报名。
- 机构只可审核 `activity.organization_id = subject` 的报名。
- 机构可查看其活动的必要报名者资料，但不可访问报名者其他活动或报警记录。
- 活动取消后，报名历史仍按原参与双方可读。

### 4.6 报警与投递

- 受护人可读 `alert.protectee_uid = subject` 的全部自身报警和聚合投递结果，但接收人的敏感联系方式脱敏。
- 监护人只有同时满足“存在该报警面向自己的 `ALERT_DELIVERY`”时可读。当前绑定是创建投递的前提，后续解除不删除既有投递审计，但解除后只保留该次报警的最小历史视图，不开放持续位置。
- 志愿者只有存在面向自己的志愿者投递时可读该次报警。可读字段限报警时间、位置快照、位置采集时间、风险提示和处理状态。
- 接收人只能确认自己的投递，不能修改其他接收人的状态，也不能将报警标记解决。
- 只有报警所属受护人可执行常规解决。管理员只能按治理流程追加处置备注。

### 4.7 通知

通知列表和未读数始终带 `receiver_principal_type` 与 `receiver_principal_id` 双条件。接收人只能标记自己的通知已读。机构账号和自然人账号 ID 即使数值相同也不得互相命中。

## 5. 管理权限

### 5.1 权限代码

| 权限代码 | 能力 |
|---|---|
| `ADMIN_MANAGE` | 创建、禁用管理员和分配权限；**最高管理员**全量，**HR 管理员**仅授予读（按 ID 查询管理员账号），见 §5.2 字段限制 |
| `USER_READ` | 查看脱敏用户资料 |
| `USER_GOVERN` | 启用/禁用自然人账号 |
| `USER_MANAGE` | 用户管理：监护/受护/志愿者列表查询与逻辑删除（删除兼任志愿者仅取消其志愿者兼任） |
| `ORG_REVIEW` | 审核机构注册和重新提交 |
| `ORG_GOVERN` | 禁用/恢复机构和处置机构内容 |
| `ORG_MANAGE` | 机构管理：机构列表查询与逻辑删除 |
| `BUSINESS_AUDIT` | 查看申请、报名、报警等业务审计记录 |
| `OPERATION_STATS` | 查看平台聚合统计 |
| `SYSTEM_NOTICE` | 发布平台系统通知 |

`SUPER_ADMIN` 固定拥有全部权限。`OPERATIONS` 固定拥有 `OPERATION_STATS`、`USER_MANAGE`、`ORG_MANAGE`；`HR_ADMIN` 固定拥有 `ADMIN_REGISTRATION_CODE_CREATE` 与 `ADMIN_MANAGE`（仅读）。其他权限由 `SUPER_ADMIN` 显式授予。权限变更对新请求立即生效，已签发 JWT 不得长期固化可撤销权限；Java 应用读取短时权限缓存并支持主动失效。

### 5.2 管理员字段限制

即使具备治理权限，管理员也不得读取或修改:

- 密码明文或密码哈希。
- 完整 JWT、刷新令牌和第三方推送凭证。
- 导航原始摄像头帧。
- 非报警处置所需的实时位置。
- 受护人代表本人做出的绑定确认。
- 报警接收人的确认结果或受护人的解决结果。

## 6. 业务关联校验

| 关联字段 | 写入方 | 写入校验 |
|---|---|---|
| `guardian_binding.guardian_uid/protectee_uid` | Java | 双方账号存在，角色分别正确且状态可用 |
| `service_application.applicant_uid/protectee_uid` | Java | 申请主体合法；代申请时绑定为 `ACTIVE` |
| `activity_enrollment.volunteer_uid` | Java | 志愿者存在、账号可用 |
| `alert.protectee_uid`、`alert_delivery.receiver_id` | Java | 创建者与令牌一致；接收人按路由事务固化 |
| `navigation_session.protectee_uid` | Python | `PROTECTEE` JWT 有效且与会话主体一致 |
| 审核记录 `admin_id` | Java | 管理员存在且具备对应权限 |

业务表位于同一个数据库，可使用物理外键保护存在性；角色、账号状态、绑定状态和权限必须由应用层校验。Java 内部模块直接在同一事务中查询，不发起内部 HTTP 调用。

## 7. 服务端鉴权顺序

每个受保护请求按以下顺序处理:

1. Java 或 Python 入口验证签名、有效期、发行方和主体类型。
2. Java 业务模块或 Python 导航模块确认账号/会话可用，验证所需角色或权限代码。
3. 按 URL 中资源 ID 加载资源；不存在返回 `404`。
4. 根据令牌主体施加行级拥有者或关系条件；存在但无权返回 `403`。
5. 校验资源当前状态和版本；冲突返回 `409`。
6. 仅接受字段白名单，忽略或拒绝受控字段。
7. 执行业务事务并写入审计、`trace_id` 和操作者主体。

对需要避免资源枚举的公开查询，可统一返回 `404`；同一接口必须保持一致策略。

## 8. 必测越权场景

1. 监护人访问未确认或已解除关系的受护人位置，返回 `403`。
2. 非监护人调用受护人创建接口，返回 `403`；初始永久绑定不得被普通解除接口终止。
3. 监护人伪造 `protectee_uid` 为未绑定受护人代申请，返回 `403`。
3. 志愿者读取未投递给自己的报警，返回 `403` 或一致的 `404`。
4. 机构处理其他机构的申请或报名，返回 `403`。
5. 普通管理员调用管理员授权接口，返回 `403`。
6. 客户端修改请求体中的拥有者 ID，服务端仍以令牌主体写入或拒绝。
7. 解除绑定后使用旧页面或缓存令牌读取位置，返回 `403`。
8. 自然人 ID 与机构 ID 数值相同，不得读到对方通知。
9. 管理员无位置权限时调用实时位置接口，返回 `403`。
10. `[FULL]` 路由或功能开关默认不可访问，不得因任意 MINI 角色而开放。
