# SullivanMINI 开发日记：2026-10-27（管理员治理与权限即时生效）

**开发主题:** 管理员权限分配补全 —— 新增 `ADMIN_GOVERN` 管理员治理权限，角色=权限集运行期可管，权限变更对下一请求立即生效
**适用范围:** SullivanMINI `[MINI]`
**变更类型:** 功能新增（含一处鉴权行为修正，非破坏性）
**关联文档:** `03-角色权限与数据范围.md` §5 / `05-数据模型与数据字典.md` / `docs/final/api/openapi.yaml` 管理员段 / `17-开发日记-2026-10-26-数据库重构与Python端移除.md`

## 1. 问题：重构之后权限分配「看起来坏了」

昨天数据库基线重建（旧库不保留）后，管理员权限分配暴露出三类真实问题——前两条在重构前就存在，只是重建让它们全部重新显形：

1. **权限只在注册码签发那一刻发生，此后再无入口。** 角色与权限在「签发注册码 → 新管理员注册」时随初始角色一次性固定；运行期既看不到谁有什么权限，也没有任何授予/撤销接口。`VOLUNTEER_REVIEW` 按设计「不在任何角色固定集内，由 SUPER_ADMIN 显式授予」，但系统里根本没有授予通道——这条权限实际上永远授不出去。
2. **权限写在 JWT 里（TTL 30 分钟），变更不生效。** 登录时角色/权限被固化进令牌，之后调整角色、撤销授权，旧令牌最长 30 分钟内仍按旧权限放行。这与 `03` §5.1「权限变更对新请求立即生效，已签发 JWT 不得长期固化可撤销权限」直接矛盾，也是「权限分配改了却不生效」这一体感的直接来源。
3. **注册码页角色硬编码。** 前端写死三个角色选项，新建角色后前端不认识。

## 2. 修复：管理员权限逐请求现算

- `AdminAccessService` 新增 `resolveAdminAccess(adminId)`：每次调用从库中现算「账号状态 + 生效角色 + 汇总权限」，返回 `null` 表示账号不存在/已逻辑删除/已禁用（视为未认证）。
- `JwtAuthenticationFilter` 对 `principalType=ADMIN` 的请求不再信任 JWT 里的角色/权限声明，逐请求用上述快照重建认证；自然人/机构主体维持 JWT 声明（其角色来自 `user_role` 关系且不走 RBAC 权限）。
- 顺带补齐：`AdminAccount` 实体补 `createdAt`（列表排序用）与 `@TableLogic deletedAt`（与 `user_account` 同构，软删后查询自动过滤、逐请求鉴权自动失效）。

效果：**停用账号、停用角色、撤销角色关系、撤销角色权限**四类变更全部在管理员的下一个请求立即生效，不再等令牌过期。

## 3. 新功能：`ADMIN_GOVERN` 与角色权限集管理

### 3.1 权限与种子

- 新增权限 `ADMIN_GOVERN`（管理员治理：启停管理员账号、授予/撤销角色、调整角色权限集），出厂仅 `SUPER_ADMIN` 持有——按 `USER_MANAGE/USER_GOVERN`、`ORG_MANAGE/ORG_GOVERN` 的既有命名法，`ADMIN_MANAGE` 保持「查看」语义（HR 管理员的只读窗口），治理写操作归 `ADMIN_GOVERN`。
- `AdminSeedInitializer` 的角色-权限映射整理为声明式 `ROLE_GRANTS` 表（`HR_ADMIN`、`OPERATIONS` 出厂集不变，含此前已实现但文档漏记的 `ORG_REVIEW`），并把 `ensureGrant` 改为真正的 upsert（复用 REVOKED 旧行置回 ACTIVE）——`uq_admin_role_permission` / `uq_admin_account_role` 两条唯一键下，「撤销后再授予 = 更新状态」是数据库注释里的既定语义，盲目 insert 会撞键。

### 3.2 接口（`AdminAccountController` / `AdminRoleController`）

| 端点 | 权限 | 说明 |
|---|---|---|
| `GET /admin/admins`、`GET /admin/admins/{id}` | `ADMIN_MANAGE` | 管理员列表/详情，带实时角色与权限汇总 |
| `POST /admin/admins/{id}/status` | `ADMIN_GOVERN` | 启用/停用（停用立即生效） |
| `POST /admin/admins/{id}/roles` | `ADMIN_GOVERN` | 授予角色（可带过期时间，upsert） |
| `DELETE /admin/admins/{id}/roles/{roleCode}` | `ADMIN_GOVERN` | 撤销角色（行置 REVOKED 留审计） |
| `GET /admin/roles`、`GET /admin/permissions` | `ADMIN_MANAGE` | 角色清单（含权限集与成员数）/ 权限字典 |
| `POST /admin/roles` | `ADMIN_GOVERN` | 新建角色（权限集打包） |
| `PUT /admin/roles/{roleCode}/permissions` | `ADMIN_GOVERN` | 全量覆盖式调整权限集（缺的授予、多的撤销） |
| `DELETE /admin/roles/{roleCode}` | `ADMIN_GOVERN` | 停用自定义角色（非物理删除：角色行被注册码/授权关系外键引用） |

### 3.3 防锁定底线（全部在写路径先守卫后落库）

1. 不能停用当前登录的管理员自己；
2. 任何变更后系统必须仍保有**其他**至少一名 `ENABLED` 的 `SUPER_ADMIN`（自己撤销自己仅有的 SUPER_ADMIN、停用最后一个他管最高管理员、停用唯一超管所在角色，都被 409 拦截）；
3. `SUPER_ADMIN` 角色权限集固定全量不可调整；
4. 系统内置角色不可停用；仍有生效成员或可用注册码的角色不可停用；
5. 授予 `SUPER_ADMIN` 仅限本身持有该角色的管理员（注册码之外的第二条受控通道）。

## 4. 前端（admin-web）

- 新增「管理员管理」页（`/admins`，`ADMIN_MANAGE` 可见；启停与分配角色按钮按 `ADMIN_GOVERN` 裁剪）：列表含实时角色/权限标签，分配角色对话框按角色开关切换授予/撤销，授予时可带过期时间。
- 新增「角色权限」页（`/roles`）：角色卡片式表格 + 权限勾选矩阵，支持新建角色、全量覆盖调整权限集、停用自定义角色；`SUPER_ADMIN` 的调整入口固定禁用并说明原因。
- 注册码页角色下拉改为 `GET /admin/roles` 动态加载——新建角色后无需改前端。
- 导航按权限裁剪新增两个入口；`AdminAccessService`/`AdminGovernDtos`/`types/api.ts` 同步补类型。

## 6. 遗留与后续

1. 权限字典中 `USER_READ` / `USER_GOVERN` / `ORG_GOVERN` / `BUSINESS_AUDIT` / `SYSTEM_NOTICE` 仍无消费方（接口未实现），继续作为预留能力挂在角色编辑器里；
2. `openapi.yaml` 中 `/admin/accounts`（创建管理员）等预留桩仍未实现，本次新增路径已按实际实现登记；
3. `03` §5.1 曾预设「Java 应用读取短时权限缓存并支持主动失效」——本次以逐请求查库直接满足「立即生效」语义（等效 TTL=0 的缓存）；`19` §Redis 能力清单里的「短时权限缓存」属并发规模优化项，若日后需要，再引入短 TTL 缓存不迟；
4. JWT 仍保留角色/权限声明（仅供登录响应与调试观察），鉴权已不依赖；下轮清理可考虑从 ADMIN 令牌中剔除以缩小令牌面。
