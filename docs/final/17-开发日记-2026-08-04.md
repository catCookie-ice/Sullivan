## 1. 今日目标

完成 Java 后端的自然人、机构和管理员注册能力，落实监护人与受护人的绑定规则，并让应用具备可重复的最高管理员初始化流程。随后使用本机 MySQL 做一次真实启动验证，确认 Flyway、数据库连接、Spring Boot 和健康检查能够串通。

## 2. 完成内容

### 2.1 Java 后端基础

- 使用 Spring Boot 3.3.4、Java 21、MyBatis-Plus、Flyway、MySQL、JWT 和 Actuator。
- 配置单一 `sullivan` 数据库，Java 应用负责 Flyway 迁移。
- 配置 JWT 无状态认证、统一密码哈希、登录和健康检查端点。
- 增加用户、资料、角色关系、机构和管理员相关的数据访问层、服务层与 Controller。

### 2.2 注册与绑定

- 自然人自主注册仅允许 `GUARDIAN` 或 `VOLUNTEER`。
- 监护人创建受护人时，在同一事务中创建受护人账号、资料和永久主绑定。
- 监护人可以通过 `user_role` 增加 `VOLUNTEER` 角色，不重复创建账号。
- 其它监护人绑定采用申请、确认状态流转；只有确认后的有效绑定才授予关系权限。
- 机构注册初始为 `PENDING`，等待后续审核流程。

### 2.3 管理员注册与初始化

- 管理员注册必须使用一次性注册码。
- 数据库只保存注册码的 SHA-256 哈希，核销成功后立即标记为已使用。
- `SUPER_ADMIN` 或 `HR_ADMIN` 可以创建注册码；HR 管理员不能签发 `SUPER_ADMIN` 或 `HR_ADMIN` 注册码。
- 启动时如果不存在启用的 `SUPER_ADMIN`，应用读取 `BOOTSTRAP_ADMIN_LOGIN`、`BOOTSTRAP_ADMIN_PASSWORD` 和 `BOOTSTRAP_ADMIN_DISPLAY_NAME` 创建最高管理员；配置缺失时拒绝启动。
- 初始化种子包含 `SUPER_ADMIN`、`HR_ADMIN`、`OPERATIONS` 及相关权限。

## 3. 数据库迁移

新增 `server-java/server-java/src/main/resources/db/migration/V1__registration_identity.sql`，覆盖注册身份、角色关系、永久绑定、机构登录字段、管理员角色权限和管理员注册码。

真实启动中发现 MySQL 9.1 不接受 `ALTER TABLE ... ADD COLUMN IF NOT EXISTS`。迁移已改为查询 `information_schema.columns` 后动态执行追加字段，兼容新表和已有旧表。随后又修正了两个超过 `CHAR(26)` 的固定种子 ID，使迁移能够完整执行。

本次失败迁移在本地数据库中通过 Flyway `repair` 清理失败记录后重新执行。该操作只针对本地验证库；正式环境应先备份并按部署流程处理失败迁移。

## 5. 问题与处理

1. 首次 Maven 编译使用 JDK 17，而项目目标版本是 Java 21，改用 `C:\Program Files\Java\jdk-21.0.10` 后编译和测试通过。
2. MySQL 9.1 拒绝迁移中的 `ADD COLUMN IF NOT EXISTS`，改为 `information_schema` 条件判断加动态 SQL。
3. 固定种子 ID 超过 `CHAR(26)`，统一修正为 26 字符。
4. 非事务性 DDL 失败后留下 Flyway 失败记录，使用 Flyway `repair` 后重新启动验证。
5. MySQL 9.1 高于当前 Flyway 10.10.0 已测试支持的 MySQL 8.1，启动会给出兼容性警告，当前验证仍然通过。
