# SullivanMINI 开发日记：2026-10-18

**开发主题:** 补齐 `client-web` 已实现接口的 Android 操作界面，并把全端 UI 换成新艺术运动风（Art Nouveau）
**适用范围:** SullivanMINI `[MINI]`，`client-android/client-ward`（不改服务端）

## 1. 今日目标

`client-web` 的四个前端里，`user-web`（监护/志愿者）与 `protectee-web`（受护人）已经接上了真实后端。
`client-android/client-ward` 这次之前只做了**扫码绑定、扫码登录、受护人端侧障碍检测**三件事：
登录页没有注册/找回入口，监护人主页只有两张扫码卡片，志愿者入口点了弹「尚未实现」，
受护人登录后没有主页。也就是说 **web 端已实现的功能，Android 端缺了一半以上**。

本次做两件事，且**只动 Android 端**：

1. 把 `user-web` + `protectee-web` 实际调用到的接口，做成对应的 Android 操作界面；
2. 全端统一换用新艺术运动风（羊皮纸底、墨线、古金/深青/苔绿/陶土色、有机不对称圆角、
   藤蔓卷须分隔线、衬线标题）——**含此前已有的页面**。

已确认的口径（用户选定）：

| 问题 | 结论 |
|---|---|
| 覆盖哪几端 | **监护人 + 志愿者 + 受护人**。机构端（`org-web`）与管理端（`admin-web`）是桌面控制台，**不做** |
| 风格范围 | **全部界面统一**，包括按既定口径不能动的受护人相机页浮层 |
| 受护人结构 | **保留免登录的端侧障碍检测入口**，另加**登录后的主页** —— 绑定码、绑定关系、公益活动、实时会话都挂在账号上 |

三个关键决定：

- **字体不打包进 APK**：标题走 `android:fontFamily="serif"`（系统的 Noto Serif），
  靠 `letterSpacing` 做出海报式字距。正文**保持无衬线** —— 受护人是低视力用户，
  小字号衬线反而更难读。以后若引入 `.ttf`，只需改各 `TextAppearance` 的 `fontFamily` 一处。
- **`level_clear/caution/danger` 不并入新色板**：它们表达的是「走得过去 / 注意 / 停下」，
  必须保持绿/黄/红的高辨识度，不能被装饰性的低饱和配色同化。
  `Theme.Sullivan.Camera` 亦保持纯黑底。
- **XML 做不到真正的曲线描边**：`<shape>` 只支持圆角矩形。「有机感」由
  *不对称圆角 + 偏移错位双框 + 卷须 vector 点缀* 三者叠加实现，
  而不是硬做一个波浪边卡片。

### 2.3 认证流程

- **注册后自动登录**：web 端注册完把用户丢回登录页重打一遍密码；Android 直接拿刚填的凭据换令牌。
  自动登录失败**不回滚注册**（账号已经建好了），提示写成「注册成功（登录名 X），但自动登录失败」并回填登录名。
- **找回密码是一个诚实的死胡同**：后端没有重置密码的接口，所以 Android 版老老实实做成
  「登录名 → 选方式并补全 → 验证结果」三步，第三步明确写出「验证通过并不等于密码已重置」。
  页面上**不出现「发送验证码」**：没有这个接口，放一个按钮就是骗人。
- **登录后的找回提醒**（`RecoveryReminderDialog`）：只在服务端 `recoveryReminder=true` 时弹，
  三个分支（现在设置 / 下次再说 / 不再提醒）**都调对应接口**，失败只写日志不阻断；
  唯一会把错误显示给用户的是「现在设置」里那次 `PUT`。
- **登录后去哪只有一处判断**：`LoginActivity.homeIntentFor()`。账密登录、注册后自动登录、
  已登录直接进主页三条路径都从这里取 Intent。分流看**服务端返回的 `roles`**，不看入口提示；
  只有「是志愿者且不是监护人」才进志愿者主页。

### 2.4 监护人 / 志愿者 / 受护人

- **监护人主页**改成入口网格：两张扫码卡（保留）+ 绑定管理 / 创建受护人 / 公益活动 /
  实时会话 / 志愿者申请 / 退出登录。「志愿者申请」在 `roles` 已含 `VOLUNTEER` 时隐藏 ——
  一个永远只会得到「已存在待审核申请」的入口，比没有这个入口更让人困惑。
- **志愿者主页**只有四张卡，并把「后端还没做」直接写在页面上：
  web 端的「接收附近的协助请求」「我的报名记录」是 `el-empty` 占位，**后端没有对应接口**，
  所以 Android 端不画那两个入口。「志愿者兼任申请」与「切到监护人视角」两张卡
  按 `roles` 是否含 `GUARDIAN` 显隐（服务端只接受监护人提交申请）。
- **受护人主页**把「不需要账号」和「跟着账号走」分成上下两块：
  第一张卡永远是「开始障碍检测」，**永远可点**，登录态、令牌过期、断网都不影响它；
  下面四张卡在未登录时**不隐藏**（受护人看不到「登录之后有什么」，就没有理由去登录），
  点它们先走扫码登录，登完直接进目标页。
  `RoleEntryActivity` 的受护人卡片改指 `ProtecteeHomeActivity`；
  相机页右上角的「我的绑定码」入口保留。

### 2.5 三处共用组件（只抽这三样）

| 类 | 理由 |
|---|---|
| `ui/common/components/StatusLabels` | 状态码在四个列表页重复出现，且服务端是**松散字符串**。各写一份 switch，迟早出现「PENDING 在绑定页叫待确认、在会话页叫等待中」——用户看到的是同一个后端字段，两种叫法只会让他以为这是两回事。未知值一律中性色 + 原样显示，不崩也不留空 |
| `ui/common/components/StateView` | 「加载中/空/失败」最容易出的分歧不是外观，而是**把「空」当成「错误」**：第一次打开绑定管理看到红色「加载失败」，其实只是还没绑过人。空态**不给重试按钮** |
| `ui/common/components/SimpleListAdapter` | 三个列表共用一套 Adapter，行布局仍各自手写 |

另有纯函数 `ui/common/components/ServerTime`：只做字符串截断与替换，
**绝不在客户端解析时区** —— 服务端给的是 `LocalDateTime`（无时区），
解析再按本机时区渲染会让显示的小时数整体偏移。

**不抽**：base Activity、通用 Toast、通用对话框工厂。现有代码里每个 Activity 独立、
错误提示各有自己的位置，强行统一反而要改协议。

### 2.6 网络层与长连接

- REST 全部走已有的 `ApiClient` / `ResultCallback`（回调已收敛到主线程）。
- `service/websocket/RealtimeSocket`：OkHttp 自带的 `newWebSocket()`，不引第三方库。
  **地址拼接是纯静态函数且有单测**：端点 `/ws/realtime` 在**服务器根路径**，
  不在 `/api/v1/` 下，而 Android 手上的 `baseUrl` 是带 `/api/v1/` 的，必须削掉。
  这是整个流程里最容易写错、写错了又最难看懂的一处（表现是握手 404）。
- **不做断线重连、不做前台服务**（web 端也没有）。会话是「当面用一下」的短时对话，
  断了就回列表重进，比做一个看不见的重连状态机、并在重连失败时让用户对着一个其实已经死掉的
  输入框打字要诚实得多。`onStop()` 即断开。
- **消息不留存**：中继是纯转发、服务端不落库，所以断开时把日志面板整个收起来，
  而不是留着让人以为「这些还能翻回来」。

### 2.7 扫码之外的两处刻意减负

- **实时会话不让用户手填「对方 UID」**：web 的 `RealtimeDemo.vue` 让用户填，因为那一页是调试页；
  手机上的问题永远是「和谁说话」，而对方在会话记录里本来就有。
- **公益活动用「加载更多」而不是页码**：手机上的列表是连续滚动的，
  给页码就得让用户在滚动和点页码之间来回切。

## 3. 与既有文档的偏离 / 决策

### 3.1 受护人入口从「直达检测页」改为「直达主页」

### 3.2 志愿者入口不再是「尚未实现」

`17-开发日记-2026-10-16` 与本仓库此前的 `AndroidManifest.xml` 都写着
「志愿者主页尚未实现，点了弹提示」。本次实现了 `VolunteerHomeActivity`，
manifest 里那条「声明一个指向不存在类的 Activity 会留下点了就崩的入口」的注释随之删除。

### 3.3 受护人相机页只换皮，不换骨

相机页是本工程对无障碍最敏感的一屏。本次在该页只改配色/字体/按钮背景，**未改**：
提示文字字号下限（≥ 22sp）、组件顺序、`contentDescription`、
`level_clear/caution/danger` 三个安全色、`Theme.Sullivan.Camera` 的黑底。
新增的装饰 vector 一律 `android:importantForAccessibility="no"`。

## 5. 已知风险

- **`usesCleartextTraffic="true"` 仍在**：后端是明文 HTTP，登录密码、二维码票据、
  最终令牌对同网段任何人都可见。见 `19-待办-安全与性能加固.md`。本次新增的接口
  （注册、找回、实时会话）同样跑在这条明文链路上，**风险面比上次更大**。
- **令牌仍明文存 SharedPreferences**：理由与 2026-10-16 的决策一致
  （网络层没上 TLS 之前，单独加密令牌挡不住实际的威胁模型）。
- **`isLoggedIn()` 不代表令牌有效**：401 时各页统一 `session.clearLogin()`，
  但**不自动跳登录页** —— 跳转会连带清掉用户已经拉到的内容，而他多半只是想再看一眼。
- **`serverBaseUrl` 是构建期常量**：真机联调时若地址不对，首屏就是「网络连接失败」。
- **新依赖只有一个**：`androidx.recyclerview:recyclerview:1.3.2`（其实已由 material 传递引入，
  显式声明是为了版本可控）。没有引入 Compose / Hilt / 字体库 / 图片库。
- **R8**：新 DTO 全部在 `data/api/dto/**`，已有 keep 规则覆盖；
  不要把 DTO 挪到别的包。

## 7. 遗留问题

- **web 端志愿者端其余页面在服务端不存在**：附近的协助请求、报名记录都还是占位。
  Android 端因此不画这两个入口，只在志愿者主页写了一句说明。
- **「我的位置 / 报警记录」同样没有接口**：`user-web` 里也是占位页，本次未做。
- **受护人相机页的端侧检测未重新跑真机**：本次只换了浮层样式，

- **`GET /activities` 需要登录**：受护人主页的公益活动卡在未登录时先引导扫码登录，
  不直接请求后弹 401。
