## 1. 今日目标

清理 `18-待办-优化前端表现.md` 里积压的前端问题，并把仍然指着「后端接口开发中」的
占位页换成真实数据。约束：不得展示不可用入口、不得返回伪成功或静态演示数据、
界面不得出现 uid。

## 2. 关键判断：以运行中的服务端为唯一事实来源

`docs/final/api/openapi.yaml` 里有 `/admin/stats/overview`、`/services`、`/applications`、
`/enrollments`、`/notifications`、`/guardians/locations/{uid}`、`/organizations/profile`，
但**运行中的服务端 `/v3/api-docs` 里没有这些路径** —— 设计稿跑在了实现前面。

因此本轮做了两件事：

1. 能用现有接口拼出来的页面，就用现有接口真实拼出来（报警页、活动列表、运营统计）；
2. 拼不出来的，把**菜单入口隐藏**（`NavItem.show: false`），页面文件保留待后端就绪，
   而不是留一个点进去只有「敬请期待」的死入口。这是 `00` §6.2 第 3 条的硬要求。

## 3. 完成内容

### 3.1 打包体积：1021 kB → 152 kB

主 chunk 超 500 kB 的根因不是「element-plus 太大」，而是 `main.ts` 里的
`app.use(ElementPlus)` 把整个组件库全量注册了一遍，`unplugin-vue-components`
的按需引入完全失效，Rollup 也无法 tree-shake。

移除该注册后，组件与指令仍由 resolver 按需引入；唯一的副作用是中文语言包丢失，
改在 `App.vue` 用 `<el-config-provider :locale="zhCn">` 提供 —— 它只影响分页
「共 N 条」、空表「暂无数据」这类文本默认值，不注册任何组件。

配套把 `ElementPlusResolver` 设为 `{ importStyle: false }`（UI-01）：
`main.ts` 的 `index.css` 成为唯一样式来源，消除按组件重复注入。
四端 CSS 合计从 525–578 kB 降到 374–379 kB。

### 3.2 响应式导航

新增 `client-web/shared/nav/AppNav.vue`（四端共用）：>900px 是原来的横向便签菜单，
≤900px 自动切成汉堡按钮 + 抽屉。用 `matchMedia` 而不是监听 `resize`，
只在跨过断点时触发一次；抽屉项是 `router-link`，触控目标 44px，
带 `aria-expanded` / `aria-current`，当前页高亮取「最长前缀匹配」
（否则 `/activities/create` 这样的子路由不会高亮任何菜单项）。

四端布局各加了一个 `.skip-to-content` 跳转链接，键盘用户第一个 Tab 即可跳过导航。

### 3.3 无障碍加固层

新增四端逐字节一致的 `src/styles/a11y.scss`，与 `global.scss` 分离：
后者负责「像手绘笔记本」，前者只管「键盘能用、读屏能读、窄屏不溢出」。
内容包括 `:focus-visible` 统一焦点环（含 Element Plus 包裹层）、`.sr-only`、
窄屏表单纵向排列、弹窗限宽、分页换行、`prefers-reduced-motion`。

### 3.4 一个被误判为「字体回退」的真实缺陷

UI-02 原本登记的是「验证断网时字体回退」。实测发现真正的问题是**字形本身**：
`ZCOOL KuaiLe` 的 `0` 是一个细长的空心方框，在 30px 以上非常像缺字形的豆腐块。
它骗过了我第一轮判断 —— 用 canvas 量字宽时 `0` 是 31.97px、`1` 是 17.47px，
宽度各不相同，说明字体确有该字形（真缺字形会回退到系统字体、宽度趋同）。
把 `0-9` 与 sans-serif 并排渲染截图后才确认。

修法：新增 `--font-num` 数字字体栈与 `.num` 工具类，只用在「数字本身就是内容」
的位置（统计大数、图表读数）。手写体仍用于标题、品牌名这些装饰性文字。

### 3.5 真实数据接入

- **监护人报警页**：`GET /alerts` 一次返回「自己发起的」和「投递给自己的」，
  监护人侧无需额外接口。展示位置新鲜度（阈值与服务端 `LocationService.STALE_AFTER`
  对齐，10 分钟）、逐接收人投递结果、高德 URI 打点。
  「结束报警」只对自己发起的显示 —— 监护人点它会被后端 403。
- **运营统计**：`/admin/stats/overview` 不存在，改为并发调三个列表接口各取 `total`，
  用 `Promise.allSettled` 语义让某一块失败不影响其它块出数字，并在页面上明示口径。
- **志愿者活动列表**：`GET /activities`。注意**没有报名接口**，界面如实说明
  「在线报名功能尚未开放」，而不是放一个点了没反应的按钮。

### 3.6 修复：输入框「打字没反应」（UI-11）

`ActivityCreate.vue` 用 `suppressLocationInput` 布尔标志防止程序化写入触发补全逻辑，
但程序化赋值 `v-model` **不会触发原生 `input` 事件**，标志永不复位，
用户的下一次真实按键被吞掉。改为记录 `lastProgrammaticText` 哨兵值做内容比对。

## 4. 验证方式

`type-check` 与 `build` 只能证明能编译，发现不了白屏、窄屏溢出、中文变英文、字形异常。
因此在 `client-web/tools/` 补了一套基于 DevTools Protocol 的端到端脚本
（用法见 `client-web/tools/README.md`）：

- 本机库里的密码都是 BCrypt 散列且未知，改库会污染开发数据，
  故用 `.env` 里同一个 `app.jwt.secret` 签调试令牌，走与后端 `JwtAuthenticationFilter`
  完全相同的校验路径；
- 逐页断言选择器与文案、切 390×844 检查抽屉与横向溢出、收集运行时 JS 异常；
- 单独验证了抽屉交互（`aria-expanded` 翻转、高亮唯一、跳转后自动关闭）、
  活动详情弹窗、中文语言包回归。

四端实测：admin 9/9、user 9/9、org 7/7、protectee 7/7，运行时异常 0 条。

## 6. 过程中的两个教训

- **不要用 PowerShell 批量重写源文件**。一次正则替换因字符串里的反引号破坏了正则，
  循环仍然执行了写入，把 27 个文件截断成 0 字节（已全部 `git checkout` 恢复）。
  批量改代码改用 Node 脚本或逐文件 `edit`。
- **PowerShell 5.1 读无 BOM UTF-8 会破坏中文**（控制台里出现 `鐢ㄦ埛` 之类的乱码）。
  这只影响显示与 `ConvertFrom-Json` 的结果，磁盘上的文件是好的；
  凡是需要处理中文的脚本一律用 Node 跑。
