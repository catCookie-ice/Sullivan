## 3. 产品定位

SullivanMINI 是面向视障受护人及其支持网络的公益服务平台，以全景分割辅助出行、安全报警、监护协作、公益服务和志愿活动为核心。平台连接受护人、监护人、志愿者、公益机构和平台管理员。

MINI 的公益服务、活动报名和平台使用均免费，不包含商品、价格、订单、支付、退款、钱包、抽成或收费入口。不得以“预留”名义要求用户支付或要求机构充值。

全景分割输出仅为辅助提示，不替代盲杖、导盲犬、交通规则、监护人或专业判断。客户端必须能在导航不可用时明确提示风险。

## 4. MINI 当前范围

### 4.1 角色

| 角色 | 标识 | 当前职责 |
|---|---|---|
| 受护人 | `PROTECTEE` | 由监护人创建账号并永久绑定初始监护人；登录、导航、语音控制、位置上报、报警、申请公益服务 |
| 监护人 | `GUARDIAN` | 注册登录、创建受护人、发起其它绑定、查看位置、接收报警、代申请公益服务 |
| 志愿者 | `VOLUNTEER` | 注册登录、维护可服务状态和位置、报名活动、接收无监护人场景的附近求助；监护人可通过角色关系兼任 |
| 公益机构 | `ORGANIZATION` | 注册并接受审核、发布免费服务和活动、处理申请和报名 |
| 管理员 | `ADMIN` | 用户与机构治理、机构审核、运营统计和必要的状态处置 |

自然人注册时选择 `GUARDIAN` 或 `VOLUNTEER`。监护人后续兼任志愿者时，在 `user_role` 关系表增加 `VOLUNTEER` 角色，不复制账号。受护人不能自主注册，必须由监护人创建；创建时写入不可解除的初始 `ACTIVE` 绑定，但之后仍可接受其它监护人绑定。

### 4.2 客户端

| 客户端 | `[MINI]` 入口 | 约束 |
|---|---|---|
| Android 原生客户端 | 受护人、监护人、志愿者 | Kotlin；受护人模式支持 Camera2、TalkBack、STT 和 Android 本地 TTS |
| 响应式 Web | 监护人、志愿者、公益机构、管理员 | 桌面与移动浏览器均可用；按角色展示菜单 |

Android 登录前必须提供角色选择入口。登录后以令牌中的服务端角色为准，客户端选择不得提升权限。响应式 Web 不提供受护人的实时导航能力。

### 4.3 业务能力

1. 用户注册、登录、资料维护和账号状态校验。
2. 监护人发起绑定，受护人确认或拒绝；确认前无查看位置、代申请或接收报警的权限。
3. 受护人由监护人创建并与创建者永久绑定；监护人绑定其它受护人需受护人同意，受护人主动申请绑定监护人需监护人同意（双向绑定，发起方与接收方互补）。
4. 受护人位置上报；已生效绑定的监护人查看最新位置和更新时间。
5. Android 采集图像，Python 部分完成全景分割、空间分析并返回引导文本；Android 使用系统本地 `TextToSpeech` 播报。
6. 受护人通过可访问按钮或语音指令启动/停止导航和触发报警。
7. 报警先固化记录，再按接收人规则分发并保留逐接收人投递结果。
8. 公益机构注册、管理员审核、免费服务项目发布、服务申请与处理。
9. 公益活动发布（含报名开始/结束时间与高德经纬度地点）、志愿者报名、机构审核和活动状态流转。
10. 监护人提交志愿者兼任申请，具备 `VOLUNTEER_REVIEW` 权限的管理员审核（含注册时长限制）；审核通过后追加 `VOLUNTEER` 角色。
11. 监护人与已绑定受护人建立实时会话（WebSocket 长连接与连接池），支持双向消息中继。会话类型 `[MINI]` 可达值：`VOICE`（语音会话）、`VIDEO`（视频通话）、`CAMERA`（监护人查看受护人摄像头画面，会话期间同时具备语音）、`EMERGENCY`（紧急会话，恒为视频通话）；`BASIC` 为纯消息中继保留值。媒体流走 WebRTC（`RTCPeerConnection`），信令复用既有 WebSocket 信封协议（`signal` 类型），TURN/STUN 由服务端下发。
12. 语音留言：会话一方可录制一段语音留言投递给对方，对方不必在线、不必接通即可稍后收听。留言只送「有一条留言」与短时有效的取回凭据，音频本体经鉴权端点取回。
13. 管理员按权限管理用户、机构及运营数据。

### 4.4 当前应用边界

| 部分 | 所有权 |
|---|---|
| Java 部分 `server-java` | 统一业务 API、JWT、账号、绑定、位置、报警、通知、公益、管理和审计 |
| Python 部分 `server-python` | 模型登记、帧分析、空间分析、引导文本和导航会话 |

Java 采用模块化单体，不拆分网关、用户、公益、报警或管理微服务。Python 是独立推理进程，只承担导航领域。位置热数据存 Redis Geo，业务记录存统一 MySQL，业务图片存 MinIO。

### 4.5 数据边界

- 使用一个 `sullivan` 数据库，不按服务拆分 schema。
- Java 是账号、绑定、位置、公益、报警、通知和管理数据的唯一写入方。
- Python 只读写导航领域表，不读取其他业务表。
- 同库关联可以使用物理外键，但授权仍必须结合 JWT 主体、角色、关系状态和资源状态。
- Java 与 Python 不共享 ORM 实体，数据库迁移统一由 Java Flyway 执行。

## 5. 冲突裁决

| 冲突主题 | v1.0 决策 |
|---|---|
| 受护人注册与主监护人 | 受护人必须由监护人创建；创建者永久绑定并成为主监护人 |
| 绑定生效 | 监护人发起后必须由目标受护人确认；禁止后台直接写成生效 |
| 多监护人报警 | 存在生效监护人时通知全部生效监护人，不只通知主监护人 |
| 志愿者报警广播 | 仅当报警时不存在任何生效监护人，才广播给附近且可服务的志愿者 |
| 推送失败 | 有监护人但推送失败时执行重试并记录失败，不因此广播志愿者 |
| TTS 所属 | Python 导航应用只返回引导文本；TTS 在 Android 本地执行 |
| 客户端 | Android 是受护人/监护人/志愿者多角色客户端；Web 是监护人/志愿者/机构/管理员响应式客户端 |
| 公益费用 | 所有 MINI 服务免费，无金额、支付和结算流程 |
| 数据关系 | 单库物理约束与应用层权限校验并用；不按服务拆库 |
| 活动群 | MINI 不创建活动群；活动结束只改变活动状态 |
| 视频与摄像头共享 | **已于 2026-10-26 提升为 `[MINI]`**（基线变更，见 §8 变更记录）：MINI 提供视频通话、监护人查看受护人摄像头画面与紧急视频会话；仅在会话 `ACTIVE` 期间、且双方 `ACTIVE` 绑定仍成立时可用 |

## 6. `[FULL]` 范围隔离

### 6.1 `[FULL]` 未来能力

- 商户入驻、商品、购物车、订单、支付、发货、退款和评价。
- 商户评级、平台抽成、钱包、充值、扣费和日终结算。
- AI 客服、LLM、人设、模型计费和客服人员体系。
- 一对一聊天、活动群聊、人工客服和活动指导。
- 导盲犬完整生命周期及商业服务能力。

> **已移出 `[FULL]`**：原「受护人与监护人语音/视频通话、受护人视角实时共享」一条已于 2026-10-26 提升为 `[MINI]`，见 §4.3 第 11 条与 §8 变更记录。

### 6.2 `[FULL-RESERVED]` 约束

允许在架构图、ID 命名和状态字典中标明扩展点，但必须同时满足:

1. MINI 启动、测试和运行不依赖 `[FULL]` 服务。
2. MINI 数据库不创建无当前业务用途的资金、聊天和订单数据。
3. MINI UI 不展示不可用入口。
4. MINI API 不返回伪成功或静态演示数据冒充 `[FULL]` 能力。
5. `[FULL]` 代码如未来并存，必须受独立模块或功能开关隔离，默认关闭。

## 7. MINI 发布验收门槛

MINI v1.0 只有同时满足以下条件才可声明通过:

1. `01` 中全部 `[MINI]` 功能需求通过对应验收规则。
2. 绑定、服务申请、报名和报警状态只按 `02` 的状态机转换。
3. `03` 的功能权限和行级数据权限均有服务端测试，越权请求返回 `403`，不存在资源返回 `404`。
4. 报警路由覆盖“多个监护人”和“无监护人广播志愿者”两条互斥路径。
5. Android 断网或推理失败时不会播报虚假的“安全可通行”。
6. Android 本地 TTS 可播报服务端返回的引导文本，后端不生成 TTS 音频。
7. Android 三角色入口与 Web 四角色入口均可到达各自核心功能，移动与桌面 Web 无关键内容溢出。
8. 全部公益项目和活动均无价格、支付、钱包、订单或收费交互。
9. `[FULL]` 能力未计入测试通过率、当前交付物或项目完成度。
10. 语音/视频/摄像头会话仅在双方 `ACTIVE` 绑定成立且会话 `ACTIVE` 期间可用；绑定解除、会话结束后信令立即拒绝；媒体流不经服务端落库。
11. 用户可见的用户标识一律为登录名（`loginName`）或显示名，账号 ID 只用于服务端唯一性校验与内部引用，不出现在任何面向用户的界面文案中。

## 8. 变更控制

范围变更必须记录变更日期、提出人、原因、受影响需求编号、数据/API 影响和验收影响。新增 MINI 功能须先更新本文和 SRS，再进入编码。将 `[FULL]` 提升为 `[MINI]` 属于基线变更，必须重新评估工期和验收计划；开发人员不得通过实现细节自行扩大范围。
