## 2. 完成内容

### 2.1 keep_auto 表单草稿自动保存（`client-web/shared/keep-auto`）

- **共享包**：`KeepAutoForm.vue` / `KeepAutoFormItem.vue` / `useKeepAuto.ts`，四个前端（admin/org/protectee/user-web）通过 vite alias `@shared` + tsconfig paths 引用（无复制粘贴）。
- **标识语义**：表单带 `keep-auto` → 保存整个 `model`；表单项带 `keep-auto` → 只存该字段；两者二选一。
- **保存策略**：`watch(model, deep)` 500ms 防抖写 localStorage（键 `sullivan:keep_auto:<route>`），叠加 `beforeunload`/`pagehide`/`visibilitychange(hidden)`/卸载兜底落盘，覆盖关标签、刷新、崩溃、SPA 内切路由。
- **防误存**：挂载记录"干净基线"，未改动不写不弹窗；恢复后基线保持原状，避免"恢复后不动就离开"被误删草稿。
- **恢复弹窗**：下次打开 `ElMessageBox.confirm` 询问，恢复回填 / 丢弃即清缓存；`exclude` 排除 `password` 等敏感字段不入库。
- **提交清除**：`defineExpose({ clearCache })`，提交成功调用；提交后表单未重置时靠基线重置防回写。
- **接入 6 个创作型表单**：CreateProtectee、ActivityCreate、org/user RegisterView、RegistrationCode（整表单）、VolunteerApply（单字段演示）。

### 2.3 管理员审核机构全流程

- **V4 迁移** `V4__organization_review.sql`：`organization` 加 `reviewed_by_admin_id` / `reviewed_at` / `review_note`。
- **审核接口** `POST /api/v1/admin/organizations/{id}/review`：仅 PENDING 可审；通过→APPROVED、驳回→REJECTED（驳回必填意见）；记录审核人/时间/意见；权限 `ORG_REVIEW`。
- **登录门禁修复**：`AuthService.loginOrganization` 从"仅拦 DISABLED"改为"仅 APPROVED 可登录"——补齐"审核通过前无法登录"的文档承诺（此前 PENDING/REJECTED 可登录是 bug）。
- **权限**：`OPERATIONS` 角色授予 `ORG_REVIEW`（`AdminSeedInitializer`）。
- **前端**：`OrgManage.vue` 对 PENDING 行加「通过」「驳回」操作（驳回弹必填原因）。

### 2.4 管理员注册全流程（注册码 Redis+DB 双写 → 明文存储）

- **Redis 接入**：pom 加 `spring-boot-starter-data-redis`；`application.properties` / `.env.example` 加 `REDIS_HOST/PORT/PASSWORD`。
- **创建注册码** `createCode`：DB 落库（审计字段全）后写 Redis `admin:regcode:<code>`，TTL=距过期秒数。
- **注册** `register`：优先读 Redis → 校验角色 → 原子 `DEL` 核销；Redis 不可用/无 key 回退 DB 乐观锁 claim；DB 保留 `created_by_admin_id`（创建者）、`expires_at`（过期时间）、`created_at`（创建时间）、`status`（过期标 `EXPIRED`）、`used_by_admin_id`（使用ID）。
- **明文存储重构**（最终按需求）：`V5__admin_registration_code_plaintext.sql` 重建表，明文 `code` 作主键，去掉 `id` 与 `code_hash`（不再 SHA-256）；实体 `@TableId code`；服务/Redis 键全部改用明文码。
- **前端**：新建 `admin-web/src/views/auth/RegisterView.vue` 管理员注册页（注册码+登录名+密码+显示名），`/register` 公开路由，登录页加入口。

### 2.6 前端地图交互与 keep_auto 的后续修复迭代（午后）

初版实现后，实测暴露多个交互问题，逐一修复：

- **Geocoder 插件懒加载**：JS API 2.0 中 `AMap.Geocoder` 是插件，须先 `AMap.plugin` 再实例化；`AmapPicker.resolveAddress` 改为"未就绪先加载再编码"，修复 `AMap.Geocoder is not a constructor`。
- **地图选点后抖动**：选点→emit→v-model→`watch(modelValue)` 自反馈循环导致 `setCenter` 反复触发抖动；watch 内比较传入坐标与 marker 当前位置（<1e-9）打断循环。
- **输入活动地点地图不动**：原用 `text === location.address` 短路防死循环，误挡"手输与当前点地址相同"；改为 `suppressLocationInput` 回填标志位，用户手输始终触发编码。另新增 `AmapPicker.flyTo`（`ensureMarker + setZoom(16) + setCenter`）强制定位，输入成功后地图必然移动。
- **地图选点未回填输入框**：`watch(location.address)` 仅在 address 值变化时触发，连续选同点/编码失败（address 为 undefined）时不更新；改为监听整个 `location` 对象，坐标变化即回填，address 缺失时回填经纬度文本。
- **活动地点 Tab 补全提示（可选）**：输入"李冰广场"后，在输入框后半段半透明显示完整地址（如"四川省成都市都江堰市李冰广场"），可 **Tab 补全**或保持原文；canvas 测量文本宽度定位提示；`geocodeText` 抑制 watch 回填，不强制改用户输入。
- **补全失效修复**：`watch(location)` 默认 `flush:'pre'` 异步，`suppressWatchBackfill=true` 赋值后立即被置回 false，等回调执行时守卫生效失败 → 直接补全无选择；改 `{ flush:'sync' }` 使守卫生效。
- **keep_auto 恢复弹窗叠加**：组件重复挂载（HMR/路由重进）时同一草稿弹多个 `ElMessageBox.confirm`；加模块级 `pendingPrompts: Set<saveKey>` 去重锁，弹窗期间置位、确认/丢弃后释放。
- **安全密钥缺失可诊断**：`VITE_AMAP_SECURITY_CODE` 为空时 `AmapPicker` 显示醒目错误提示（而非地图可用但编码静默失效）；Geocoder 正/逆编码失败 `console.warn` 输出 `status`/`info`。

## 3. 关键问题与处理

- **注册码 Redis 路径查不到角色**：`writeRedisCode` 的 value 中 `roleId` 实为角色 ID，`register` 却用 `getRoleCode` 匹配 → 按 ID 查询修复（与 DB 回退一致）。
- **注册码外键失败**：`used_by_admin_id` 外键 `fk_registration_code_user → admin_account(id)`，原流程在插入管理员前就回填 → 改为 `finishRegister` 先插管理员再回填；`claimFromDb` 乐观锁只置 USED 不写使用人。
- **MyBatis-Plus lambda 缓存**：单测环境 `Wrappers.lambdaUpdate` 无法解析 → 改显式列名 `UpdateWrapper`。
- **共享包依赖解析**：`../shared` 在 node_modules 之外，bare import 无法向上解析 → vite/tsconfig 对 `vue`/`element-plus`/`vue-router` 显式映射到各应用自身依赖；tsconfig `paths` 补 `@shared/*` 与 `include`。
- **重启约束**：`BOOTSTRAP_ADMIN_PASSWORD` 当前仅 6 位，不满足 `HighestAdminBootstrap` ≥12 位要求；本次按用户决定"只清数据不重启"，下次重启前需补足。
- **高德 JS API 2.0 三坑**：① `securityJsCode` 必须在脚本加载前设 `window._AMapSecurityConfig`；② `Geocoder` 是插件，须 `AMap.plugin` 加载后再实例化；③ Web 端 key 需在控制台配域名白名单，否则正/逆地理编码受 `INVALID_USER_SCODE` 限制。
- **双向联动反馈循环**：输入框↔地图双向绑定极易因"emit→v-model→watch→再 emit"形成死循环/抖动；用回填标志位（区分用户手输 vs 程序回填）与坐标相等守卫打断，而非字符串比较。
- **Vue watch 时序陷阱**：`flush:'pre'`（默认）异步回调会在同步置位/复位之间被跳过，导致"抑制守卫"失效；需要同步守卫时用 `flush:'sync'`。
