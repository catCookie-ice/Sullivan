## 1. 使用说明

本目录是项目设计与开发的唯一权威文档集。根目录及 `SullivanMINI/` 下的原文档仅作为需求来源和历史参考；内容冲突时，以本目录文档为准。

当前迭代只交付 SullivanMINI 的公益能力。完整版的商业交易、AI 客服、群聊、视频通话等能力仅做边界、接口和数据扩展预留，不属于当前验收范围，也不得因预留而引入当前运行依赖。

## 5. 当前事实

截至 2026-08-04，Java 后端已实现注册、登录、JWT、监护绑定、角色兼任、管理员注册码和最高管理员 bootstrap；单元测试、JAR 打包及本机 MySQL 真实启动验证已通过。位置、报警、导航、公益闭环和完整 HTTP 端到端验收仍按 `15` 推进。当前 Flyway 可执行迁移为 `V1__registration_identity.sql`，旧领域迁移目录尚未完成清理或合并。

截至 2026-08-12，新增找回联系方式能力（`V2__account_recovery.sql`）：自然人与机构注册可选 `recoveryPhone`/`recoveryEmail`，联系方式按"明文不加密段 + HMAC-SHA256 单向加密段"两段存储；找回密码流程已实现到"按掩码前缀补全并验证"一步（发送验证码与重置密码留空）；未设置联系方式的账号登录返回 `recoveryReminder` 提醒，支持"下次再说"（一周后）与"不再提醒"。详见 `17-开发日记-2026-08-12.md`。

截至 2026-08-17，新增 `V3__welfare_activity_volunteer_realtime.sql`：绑定双向同意（受护人可主动申请绑定监护人、接收方确认/拒绝、发起方取消、永久绑定不可解除、定时过期）、志愿者兼任申请与管理员审核（`VOLUNTEER_REVIEW` 权限 + 注册满 N 天可配置限制）、机构创建志愿活动（报名窗口 + 高德经纬度）、监护-受护实时会话（WebSocket `/ws/realtime` + 连接池，`BASIC` 类型），以及 org-web 高德地图选点组件（`VITE_AMAP_KEY` 由用户在环境配置补全）。详见 `17-开发日记-2026-08-17.md`。

截至 2026-10-11，`client-android/client-ward`（受护人端工程，当天由 `client-android/` 迁入）首次可构建，并落地受护人客户端的**端侧**障碍检测：CameraX 取像 → 端侧 ONNX Runtime 跑 YOLOv8 → 跨帧追踪测速 → 中文提示 + 本地 TTS + 振动 + 陀螺仪晃动报警，帧不出设备、不联网；并已在真机通过十项清单中的八项（未验证的两项为「无陀螺仪设备降级分支」与「模型缺失分支」，见日记 §4.7）。**这偏离 `04` UC-04 与 `06` §4 定义的服务端导航链路**（该链路登记为预留点 `NAV-01`，见 `16` §1），原服务端链路对应的客户端空壳与 `service/tts/TTSService` 已删除；模型文件按仓库 `*.onnx` 策略不入库。详见 `17-开发日记-2026-10-11.md`。

截至 2026-10-16，新增 `V6__qr_binding_login.sql`（`protectee_bind_code` 绑定码、`qr_login_ticket` 登录票据）与八个二维码接口：受护人**登录后**出示绑定码、监护人扫码**即完成绑定**（记为「受护人发起 + 监护人扫码确认」，不新增绑定状态转换，落在既有 `PENDING -> ACTIVE` 之内）；受护人**未登录**时在登录页出示登录票据，监护人扫码、从自己生效绑定的受护人中选一位并确认后，由出示设备以一次性凭据换回该受护人的令牌（令牌不出现在任何轮询响应里）。Android 端补齐了此前不存在的网络层、`SessionStore`、监护人账密登录与监护人主页，并清掉 Compose/Hilt 死依赖；二维码只做 Android 端。**受护人登录页只做扫码登录**是一个显式的授权决策，其代价（受护人没有第二条独立登录途径自证）与遗留风险（明文 HTTP、令牌无法吊销、票据端点无限流）见日记 §3.3 与 §5。同时修掉一处既有缺陷：`POST /api/v1/auth/register/user` 省略 `role` 字段过去返回 500（`Set.of(...).contains(null)` 抛 NPE），现为 400 并补了两个用例钉住（日记 §4.6）。详见 `17-开发日记-2026-10-16.md`。

同日登记后续加固待办 **`19-待办-安全与性能加固.md`**（六项，均为 `[MINI]` 范围内应做完、**不是** `[FULL]` 预留）：SEC-01 升级 HTTPS、SEC-02 完善限流、SEC-03 引入 `jti`、SEC-04 引入黑名单、SEC-05 引入 refresh（短 access + 长 refresh，吊销只需让 refresh 失效）、PERF-01 引入 Redis 减小数据库压力。其中 SEC-05 不是"新增设计"而是**补做一件已写进需求、实现时整体漏掉的功能**：双令牌在 `01` **FR-02**（「退出后当前刷新令牌必须失效」）、`04` 登录用例（「签发 JWT **与**刷新令牌」）、`15` 阶段 3 交付物、`05` §2/§4/§6、`06`、`03`、`db/schema.sql:51-68`（`auth_refresh_token` DDL）与 `api/openapi.yaml:58-64`（`/auth/refresh`、`/auth/logout`）**七处都已写明**，而服务端一行未写：`TokenResponse` 没有 `refreshToken` 字段、`AuthController` 只有 4 个路由、该表**未进任何 Flyway 迁移**。阶段 3 当时只以「登录请求 200 并拿到令牌」验收，未回头比对 `04` 的原文，欠账因此静默留存至今。实现时补齐既有那套即可（补 `V7`），**不要新建第二套路径或表**；`04` §3 UC-01 尚缺「退出」流程需一并补。`14` §4 已登记 `sv:token:revoked:{jti}`、`01` §5 已定义 `429`、`06` §6 已定 TLS 反代方向，`19` 只登记落点、不新增口径。

letterbox，代价是一次缩放、换来两者都拿到符合各自期望的输入。由此产生的新风险是"检测框在 640 几何下归一化、深度图是 768 几何"，换算时必须用**深度自己**的 letterbox 参数（用错不崩、只是采样点偏几十像素到背景地面，表现得像"深度模型不准"），已由 `DepthGeometryTest` 三条用例钉住。离线用真实权重跑 `bus.jpg`：检测得 **1 辆 bus + 4 个 person**（bus 0.925、坐标贴左缘到右缘、下沿贴地），深度得 **bus 4.08 m、4 个行人 3.21–3.89 m**，且越靠画面下方读数越小，与透视一致。据此把"近"从纯几何启发式升级为米级判断，播报改为 `"1.5 米处中央行人，注意"`（米数前置；多目标簇不报米数）。**深度的缺失是逐字节兼容的降级**：无深度/动态维度/超出 0.05–80 米时一律返回 `NaN`，判近退回原 `NEAR_BOTTOM_RATIO`/`NEAR_AREA_RATIO` 老路径，符合 `00` §7.5「不得给出自信的错误读数」。另修掉一个隐蔽的真 bug：`YoloV8Detector.decode` 输出的是**内容区**归一化坐标（已减 pad、除 content），而深度图是整张 640×640 输入；第一版直接乘 `inputSize`
