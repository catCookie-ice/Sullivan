# SullivanMINI 数据库设计补充与迁移修正

**文档版本:** v2.1  
**编制日期:** 2026-08-04  
**适用范围:** SullivanMINI `[MINI]`  
**依据:** `02`、`05` 和 `docs/final/db/schema.sql`

## 1. 架构迁移结论

原设计按四个服务和四个 schema 组织数据库，现取消微服务设计，统一改为一个 `sullivan` 数据库。Java 应用执行全部 Flyway 迁移，Python 不执行迁移，只访问导航表。

迁移顺序：

1. 将 `schema.sql` 的数据库创建和所有 `USE` 语句统一为 `sullivan`。
2. 当前 Java 实现使用 `src/main/resources/db/migration/V1__registration_identity.sql`，覆盖注册身份、角色、绑定和管理员注册所需表结构。
3. 该迁移已在本机 `127.0.0.1:3306/sullivan` 的 MySQL 9.1 上完整执行，Flyway schema version 为 `1`。
4. 旧的 `db/migration/user`、`navigation`、`welfare`、`admin` 目录仍需后续统一清理或合并；已有环境不得原地混用旧 schema 与新基线。

当前迁移中的兼容追加字段使用 `information_schema.columns` 判断后动态执行 `ALTER TABLE`，不使用 MySQL 不兼容的 `ADD COLUMN IF NOT EXISTS`。固定种子 ID 均保持 `CHAR(26)` 长度。

## 2. 必须修正的状态约束

基线合并时，以 `02-术语枚举与状态机.md` 为唯一状态口径：

| 表 | 正确值 | 修正点 |
|---|---|---|
| `guardian_binding` | `PENDING, ACTIVE, REJECTED, CANCELLED, EXPIRED, TERMINATED` | 移除旧 `REVOKED` |
| `welfare_service` | `OPEN, PAUSED, CLOSED` | 移除 `DRAFT` |
| `volunteer_activity` | `RECRUITING, IN_PROGRESS, ENDED, CANCELLED` | `ONGOING` 改为 `IN_PROGRESS` |
| `alert` | `CREATED, DISPATCHING, DISPATCHED, ACKNOWLEDGED, RESOLVED, NO_RECIPIENT, DISPATCH_FAILED` | 增加完整路由结果 |
| `alert_delivery` | `PENDING, SENT, DELIVERED, ACKNOWLEDGED, FAILED` | 移除未定义的 `CANCELLED` |

`alert` 必须拥有 `route_type`，允许 `ALL_GUARDIANS`、`NEARBY_VOLUNTEERS`、`NONE`；否则无接收人时无法记录路由事实。

## 3. Outbox 与并发

`outbox_message` 放在统一库中，由 Java 事务写入，`@Scheduled` 领取并重试：

```sql
UPDATE outbox_message
SET status = 'PROCESSING', version = version + 1
WHERE id = :id AND version = :version AND status = 'PENDING';
```

所有状态转换使用：

```sql
UPDATE {table}
SET status = :to, version = version + 1, updated_at = NOW(3)
WHERE id = :id AND version = :version AND status = :from;
```

影响行数为 0 时返回 `409`。服务申请和活动报名的名额使用条件更新或 `SELECT ... FOR UPDATE`，禁止先查后写。

## 4. Redis 约定

| 用途 | 键 |
|---|---|
| 最新位置 | `sv:loc:{principal_type}:{uid}` |
| 志愿者 Geo | `sv:geo:volunteer` |
| 可服务状态 | `sv:vol:available:{uid}` |
| 幂等键 | `sv:idem:{scope}:{principal}:{key}` |
| 权限短缓存 | `sv:perm:admin:{uid}` |
| 绑定版本 | `sv:bind:version:{protectee_uid}` |
| 令牌吊销 | `sv:token:revoked:{jti}` |

MySQL `latest_location` 是权威记录；Redis 是缓存和地理索引。关系或权限缓存必须带版本，缓存命中不能跳过 Java 的行级权限检查。

## 5. 验收检查

1. 空 MySQL 8.0.36 执行单一 V1 基线成功。
2. `information_schema.SCHEMATA` 只出现 `sullivan` 业务数据库，不出现旧四 schema。
3. `SHOW CREATE TABLE` 的状态值与 `02` 完全一致。
4. 同一绑定、报警幂等键、有效申请和有效报名的并发写入符合唯一约束。
5. 最后一个服务或活动名额并发批准只能成功一次。
6. 报警覆盖多监护人、无监护人和推送失败三条测试路径。
7. 全库不存在金额、币种、订单、支付、钱包字段，也不存在聊天和视频表。
