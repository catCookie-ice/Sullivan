## 说明

- 优先级：P1 影响正确性/可访问性，P2 影响完成度，P3 为打磨项。
- 涉及跨端一致性的改动（主题、构建、lint）需同步四个前端项目。
- 与后端接口相关的填充项（UI-05/UI-06）依赖对应后端能力就绪。
- **接口可用性以运行中服务端的 `/v3/api-docs` 为准**，不要以 `docs/final/api/openapi.yaml` 为准：
  后者是设计稿，其中 `/admin/stats/overview`、`/services`、`/applications`、`/enrollments`、
  `/notifications`、`/guardians/locations/{uid}`、`/organizations/profile` 均**未实现**。

## 本轮验证方式

仅靠 `type-check` / `build` 无法发现白屏、窄屏溢出、中文变英文、字形异常等问题，
因此在 `client-web/tools/` 下补了一套基于 DevTools Protocol 的端到端自检脚本
（用法见 `client-web/tools/README.md`）。本轮四端实测结果：admin 9/9、user 9/9、
org 7/7、protectee 7/7，运行时 JS 异常 0 条；另通过中文语言包回归（分页「共 N 条」、
空表「暂无数据」仍为中文）与窄屏抽屉交互（`aria-expanded` 翻转、当前页高亮唯一、
点击跳转后自动关闭）验证。
